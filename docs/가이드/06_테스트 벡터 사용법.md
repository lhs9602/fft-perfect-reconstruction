# 테스트 벡터 사용법

**TL;DR**: `src/testvec.py`(비교 함수)와 `src/testvec_data.py`(값) 두 파일이다. 직접 만든 함수를 `tv.check_function(함수, tv.FFT_CASES)`처럼 넘기면 16bit 샘플 형식의 입력을 넣어 보고, 다르면 **어느 자리가 다른지와 양쪽 값**을 보여 준다. `tv.compare_wav(원본, 복원)`은 먼저 **파일 전체**를 비교하고, 다르면 **밀림을 맞춘 뒤** 복원율(%)과 판정을 알려 준다.

---

## 1. 파일

| 파일 | 내용 | 고쳐도 되는가 |
|---|---|---|
| `src/testvec.py` | 비교 함수. 테스트 벡터 비교와 WAV 복원율 비교. FFT, 윈도우, IFFT를 직접 구현한 코드는 없다 | 필요하면 고쳐도 된다 |
| `src/testvec_data.py` | 입력과 기대값. 숫자만 있다 (2,968줄) | 고치지 않는다 |

`src/` 안에 있어서 `src/`의 다른 파일과 `tests/`의 시험 파일에서 `import testvec as tv`로 쓸 수 있다.

---

## 2. 벡터

### 2.1 입력 신호

모두 정수이고 16bit 샘플 범위(−32768 ~ 32767) 안이다. 길이는 512(한 프레임)다.

| 이름 | 내용 | 최소 | 최대 |
|---|---|---|---|
| `impulse` | 0번 샘플만 10000, 나머지 0 | 0 | 10000 |
| `dc` | 모든 샘플이 1000 | 1000 | 1000 |
| `sine_1khz` | 1000 Hz 사인파, 진폭 10000, 정수로 반올림 | −10000 | 10000 |
| `noise_fullscale` | 16bit 전 범위의 난수 | −32768 | 32767 |
| `speechlike` | 말소리 비슷한 합성 신호 (기본 주파수 140 Hz의 배음) | −12000 | 11528 |
| `small8` | 1000, 2000, 3000, 4000, 0, 0, 0, 0 (길이 8) | 0 | 4000 |

실제 음성은 아니다. `speechlike`는 배음에 포먼트 모양의 크기를 준 합성 신호다.

### 2.2 검사 묶음

| 묶음 | 항목 수 | 넣는 것 | 기대하는 것 | 확인 대상 | 가이드라인 |
|---|---|---|---|---|---|
| `tv.FFT_CASES` | 5 | 샘플 512개 | 스펙트럼 512개 | FFT | 단계_2, 단계_3 |
| `tv.FFT_CASES_SMALL` | 1 | 샘플 8개 | 스펙트럼 8개 | 길이 8을 받는 FFT | 단계_2, 단계_3 |
| `tv.IFFT_CASES` | 5 | 스펙트럼 512개 | 원래 샘플 512개 | IFFT | 단계_4 |
| `tv.WINDOW_512` | 1 | — | 윈도우 값 512개 | 윈도우 | 단계_5 |
| `tv.WINDOWED_CASES` | 3 | 샘플 512개 | 윈도우를 곱한 값 512개 | 윈도우 곱 | 단계_7 |
| `tv.ANALYSIS_CASES` | 3 | 샘플 512개 | 윈도우를 곱한 뒤 FFT한 스펙트럼 512개 | 윈도우 곱 + FFT | 단계_7 |

묶음 안의 항목 하나는 아래 다섯 가지를 가진다.

| 키 | 내용 |
|---|---|
| `"name"` | 이름. 예: `"fft/sine_1khz"` |
| `"input"` | 넣을 값 |
| `"expected"` | 기대값 |
| `"note"` | 설명 |
| `"abs_tol"` | 그 항목의 허용 오차 (§5) |

프레임 공급(단계_6)과 겹쳐 더하기(단계_8)의 벡터는 없다. 그 단계는 [04_구현 가이드라인.md](04_구현%20가이드라인.md)의 기대값 표와 §3.6의 복원율로 확인한다.

## 3. 쓰는 법

아래에서 `fft`, `ifft`, `make_window`, `apply_window`는 **직접 만든 함수**를 가리키는 이름이다. 실제 이름으로 바꿔 쓴다. `main`은 그 함수들이 들어 있는 파일 `src/main.py`다([04](04_구현%20가이드라인.md) §0.3). 예시는 `tests/test_main.py`처럼 `main.py`가 **아닌** 파일에 쓰는 모양이다. `main.py` 안에서 쓸 때는 `from main import ...` 줄이 필요 없다.

### 3.1 함수를 통째로 검사한다

검사 함수가 묶음의 입력을 하나씩 넣어 보고 결과를 비교한다. 넘기는 함수는 **리스트 하나를 받아 리스트 하나를 돌려주는** 모양이어야 한다.

```python
import testvec as tv
from main import fft, ifft

tv.check_function(fft, tv.FFT_CASES)
tv.check_function(ifft, tv.IFFT_CASES)
```

모두 통과하면 `True`, 하나라도 틀리면 `False`를 돌려준다.

### 3.2 윈도우를 검사한다

윈도우는 넣을 입력이 없다. 만든 값 512개를 넘긴다.

```python
import testvec as tv
from main import make_window

tv.check_window(make_window(512))
```

### 3.3 인자가 둘 이상인 함수를 검사한다

윈도우 곱처럼 인자가 둘인 함수는 `lambda`로 인자 하나짜리로 감싼다.

```python
import testvec as tv
from main import make_window, apply_window

w = make_window(512)
tv.check_function(lambda x: apply_window(x, w), tv.WINDOWED_CASES)
```

### 3.4 결과를 직접 비교한다

함수를 넘기지 않고, 계산한 결과를 기대값과 비교할 수도 있다.

```python
import testvec as tv
from main import fft

case = tv.get_case("fft/sine_1khz")
result = fft(case["input"])
tv.compare(case["name"], result, case["expected"])
```

### 3.5 pytest에서 쓴다

```python
import testvec as tv
from main import fft


def test_fft():
    assert tv.check_function(fft, tv.FFT_CASES)
```

시험이 실패하면 pytest가 검사 함수의 출력을 "Captured stdout call" 아래에 보여 준다.

### 3.6 WAV 두 개를 비교한다 — 복원율

원본 WAV와 복원한 WAV의 경로를 넘긴다.

```python
import testvec as tv

result = tv.compare_wav("data/input/sine_1k.wav", "data/output/sine_1k.wav")
print(result["percent"])
```

비교는 두 번에 나누어 한다.

| 차례 | 하는 일 | 결과 |
|---|---|---|
| 1차 | 두 파일을 처음부터 끝까지 바이트 단위로 비교한다 (표준 라이브러리 `filecmp`) | 전부 같으면 완전 복원으로 보고 **여기서 끝낸다** |
| 2차 | 1차에서 다를 때만 샘플을 비교한다 | 복원율, 밀림, 다른 위치를 알려 준다 |

2차에서 같은 위치끼리만 비교하면 복원이 한 샘플만 밀려도 0%가 된다. 그래서 **밀림을 먼저 찾아 맞춘 뒤** 비교하고, 밀림이나 위상에 덜 민감한 값도 함께 잰다.

| 재는 것 | 뜻 | 사전의 이름 |
|---|---|---|
| 파일이 같은가 | 1차의 결과. `True`이면 파일 전체가 같다 | `"file_same"` |
| 복원율 | 밀림을 맞춘 뒤 일치한 샘플 수 ÷ **원본** 샘플 수 × 100. 값이 완전히 같아야 일치다 | `"percent"` |
| 겹친 구간만 본 일치율 | 밀림을 맞춘 뒤 일치한 샘플 수 ÷ **겹친** 샘플 수 × 100 | `"overlap_percent"` |
| 그대로 비교한 일치율 | 밀림을 맞추지 않고 같은 위치끼리 비교한 값 | `"plain_percent"` |
| 밀림 | 복원이 몇 샘플 늦은가. 음수면 이르다 | `"shift"` |
| 부호 | −1이면 부호가 뒤집혔다 | `"sign"` |
| 크기 비 | 복원이 원본의 몇 배인가 | `"gain"` |
| 파형 유사도 | 밀림을 맞춘 뒤의 상관계수(%). 작은 오차에는 거의 줄지 않는다 | `"waveform_percent"` |
| 스펙트럼 유사도 | 주파수별 크기만 비교한 값(%). 위상은 보지 않는다 | `"spectrum_percent"` |
| 판정 | 위 값들로 내린 한 줄 판정 | `"verdict"` |

| 항목 | 내용 |
|---|---|
| 받는 파일 | 16bit PCM. 샘플 폭이 2바이트가 아니면 비교하지 않는다 |
| 길이가 다를 때 | 겹치는 구간만 비교한다. 복원에 없는 샘플은 일치하지 않은 것으로 센다 |
| 채널 수, 샘플링 주파수가 다를 때 | "주의"로 알리고 샘플은 그대로 비교한다 |
| 파일은 다르고 샘플이 전부 같을 때 | 판정은 완전 복원이다. 샘플이 아닌 부분(헤더 등)이 다르다고 알린다. `"file_same"`은 `False`다 |
| 원본과 복원에 같은 파일을 넘겼을 때 | "주의"로 알린다. 자기 자신과 비교하면 언제나 100%다 |
| 1차에서 끝났을 때의 사전 | 복원율과 유사도는 100, 밀림 0, 부호 1, 크기 비 1로 채운다. 따로 재지 않는다 |
| 돌려주는 값 | 위 표의 사전. 파일을 읽지 못하면 `None` |

밀림만 있는 복원은 복원율이 100%가 되지 않는다. 밀린 만큼 원본의 끝(또는 처음)이 복원 파일에 없기 때문이다. 그때는 "겹친 구간만 본 일치율"이 100%로 나온다.

### 3.7 리스트 두 개를 비교한다 — 복원율

WAV로 쓰기 전에 리스트끼리 비교할 수 있다. 반올림하기 전의 실수 값이면 `tol`로 허용 차이를 준다. 재는 것과 돌려주는 값은 §3.6의 2차와 같다. 파일을 비교하지 않으므로 사전에 `"file_same"`은 없다.

```python
import testvec as tv

original = [10, 20, 30, 40]
restored = [10.0000001, 19.9999999, 30.2, 40.6]
result = tv.compare_samples("반올림 전", original, restored, tol=0.5)
```

`tol=0.5`는 "반올림하면 같은 정수가 되는가"를 보는 값이다. `tol`을 주지 않으면 0이고 완전히 같아야 일치다.

### 3.8 어떤 벡터가 있는지 본다

```python
import testvec as tv

tv.list_cases()
```

### 3.9 함수 목록

| 함수 | 하는 일 | 돌려주는 값 |
|---|---|---|
| `tv.check_function(함수, 묶음)` | 묶음의 입력을 함수에 넣고 결과를 비교한다 | 모두 통과하면 `True` |
| `tv.check_window(값)` | 윈도우 512개를 비교한다 | 같으면 `True` |
| `tv.compare(이름, 결과, 기대값)` | 두 리스트를 자리마다 비교한다 | 같으면 `True` |
| `tv.compare_wav(원본 경로, 복원 경로)` | WAV 두 개를 비교한다. 파일 전체를 먼저, 다르면 샘플을 비교한다 | 사전 (§3.6) |
| `tv.compare_samples(이름, 원본, 복원)` | 리스트 두 개를 비교한다 | 사전 (§3.6) |
| `tv.get_case(이름)` | 이름으로 항목 하나를 찾는다 | 항목 |
| `tv.list_cases()` | 항목의 이름과 설명을 출력한다 | — |

비교 함수는 모두 `max_show=숫자`로 다른 자리를 몇 개까지 보여 줄지 정할 수 있다. 기본은 10이다.

## 4. 출력 읽는 법

### 4.1 통과

```text
[통과] fft/sine_1khz : 512개 모두 일치 (가장 큰 차이 5.709e-10, 480번 자리)
결과: 5개 중 5개 통과
```

"가장 큰 차이"는 계산 오차다. 0이 아니어도 허용 오차 안이면 통과다.

### 4.2 실패

역변환에서 $N$으로 나누지 않았을 때의 출력이다.

```text
[실패] ifft/noise_fullscale : 512개 중 512개가 다르다 (허용 오차 1e-06 + 1e-09 x |기대값|)
        자리  기대값                                  실제값                                  차이
         0  17387+0j                             8902144+0j                           8.885e+06
         1  5324+0j                              2725888+4.16076414145e-10j           2.721e+06
         2  27922+0j                             14296064-1.6526268824e-10j           1.427e+07
    ... 그 밖에 509개 (처음 다른 자리 0, 마지막 다른 자리 511)
    차이가 가장 큰 자리: 10번
        기대값 -32768+0j
        실제값 -16777216+2.28809926979e-09j
    힌트: 크기가 기대값의 N배(512배)다. N 으로 나누는 곳을 확인한다.
결과: 1개 중 0개 통과
```

| 줄 | 뜻 |
|---|---|
| 첫 줄 | 몇 개 중 몇 개가 다른지, 허용 오차 |
| 표 | 다른 자리의 번호, 기대값, 실제값, 차이. 앞에서부터 `max_show`개 |
| "그 밖에" | 표에 다 싣지 못한 개수와, 다른 자리의 처음과 마지막 번호 |
| "차이가 가장 큰 자리" | 그 자리의 양쪽 값 |
| "힌트" | 결과가 기대값과 어떤 관계인지 찾았을 때만 나온다 |

값은 `실수부+허수부j` 모양이다. 양쪽 모두 허수부가 없으면 실수만 보여 준다.

### 4.3 복원율

파일 전체가 같을 때(1차에서 끝난다):

```text
원본 orig.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
복원 ok.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
    파일 비교: 같다. 파일 전체가 바이트 단위로 같다.
[복원율] ok.wav : 100.0000 %
    판정: 완전 복원
```

샘플은 전부 같은데 헤더의 샘플링 주파수가 다를 때:

```text
원본 orig.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
복원 rate.wav : 채널 1, 샘플 폭 2바이트, 8000 Hz, 샘플 8000개
    주의: 샘플링 주파수가 다르다. 원본 16000, 복원 8000
    파일 비교: 다르다. 샘플을 비교한다.
[복원율] rate.wav : 100.0000 %
    그대로 비교       :  100.0000 %  (원본 8000개 중 8000개 일치)
    밀림              : 없다
    밀림을 맞춘 뒤    :  100.0000 %  (원본 8000개 중 8000개 일치)
    겹친 구간만 보면  :  100.0000 %  (겹친 8000개 중 8000개 일치)
    크기 비           :    1.0000    (복원 / 원본)
    파형 유사도       :  100.0000 %
    스펙트럼 유사도   :  100.0000 %
    판정: 완전 복원
    샘플은 전부 같다. 파일에서 샘플이 아닌 부분(헤더 등)이 다르다.
```

샘플의 복원은 맞았고, 파일을 쓸 때 넣은 헤더의 값이 원본과 다르다는 뜻이다.

겹쳐 더하는 위치가 496샘플 밀렸을 때:

```text
원본 orig.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
복원 late.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
    파일 비교: 다르다. 샘플을 비교한다.
[복원율] late.wav : 93.8000 %
    그대로 비교       :    0.0000 %  (원본 8000개 중 0개 일치)
    밀림              : 복원이 496샘플 늦다
    밀림을 맞춘 뒤    :   93.8000 %  (원본 8000개 중 7504개 일치)
    겹친 구간만 보면  :  100.0000 %  (겹친 7504개 중 7504개 일치)
    크기 비           :    1.0000    (복원 / 원본)
    파형 유사도       :  100.0000 %
    스펙트럼 유사도   :   99.7296 %
    판정: 값은 같고 위치만 밀렸다. 겹쳐 더할 때의 위치를 확인한다
```

그대로 비교하면 0%이지만, 밀림을 맞추면 겹친 7,504개가 모두 같다. 복원율이 93.8%인 것은 원본의 끝 496개가 복원 파일에 없어서다.

입력이 끝난 뒤 0으로 된 프레임 31개를 넣지 않았을 때:

```text
원본 orig.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
복원 noflush.wav : 채널 1, 샘플 폭 2바이트, 16000 Hz, 샘플 8000개
    파일 비교: 다르다. 샘플을 비교한다.
[복원율] noflush.wav : 93.9375 %
    그대로 비교       :   93.9375 %  (원본 8000개 중 7515개 일치)
    밀림              : 없다
    밀림을 맞춘 뒤    :   93.9375 %  (원본 8000개 중 7515개 일치)
    겹친 구간만 보면  :   93.9375 %  (겹친 8000개 중 7515개 일치)
    크기 비           :    0.9690    (복원 / 원본)
    파형 유사도       :   98.7730 %
    스펙트럼 유사도   :   99.9922 %
    판정: 일부만 복원되었다. 다른 위치를 확인한다
    밀림을 맞춘 뒤에도 다른 샘플 485개 (허용 차이 0)
         원본 위치  원본               복원               차이
          7514  -5007            -5006            1
          7515  -7914            -7912            2
          7516  -10981           -10977           4
    ... 그 밖에 482개
    처음 다른 위치 7514, 마지막 다른 위치 7999
```

"처음 다른 위치"와 "마지막 다른 위치"를 보면 어느 구간이 틀렸는지 알 수 있다. 위 예는 끝의 486샘플 구간이다.

위상만 달라졌을 때(주파수별 크기는 그대로 두고 위상을 바꾼 신호):

```text
[복원율] phase.wav : 0.0000 %
    그대로 비교       :    0.0000 %  (원본 8000개 중 0개 일치)
    밀림              : 복원이 2892샘플 늦다, 부호가 반대다
    밀림을 맞춘 뒤    :    0.0000 %  (원본 8000개 중 0개 일치)
    겹친 구간만 보면  :    0.0000 %  (겹친 5108개 중 0개 일치)
    크기 비           :    0.0611    (복원 / 원본)
    파형 유사도       :    6.1224 %
    스펙트럼 유사도   :   99.7971 %
    판정: 주파수별 크기는 같고 파형이 다르다. 위상이 달라졌다
```

파형은 전혀 닮지 않았는데 스펙트럼 유사도가 높다. 이때 나온 "밀림"은 뜻이 없다 — 어떻게 겹쳐도 닮지 않아 그나마 나은 자리를 고른 것이다.

### 4.4 판정

| 판정 | 조건 | 먼저 볼 곳 |
|---|---|---|
| 완전 복원 | 파일 전체가 같다(1차). 또는 그대로 비교한 일치율이 100%이고 길이가 같다(2차) | — |
| 값은 같고 위치만 밀렸다 | 겹친 구간이 전부 같고 밀림이 0이 아니다 | 겹쳐 더할 자리 ([03](03_지식과%20공식.md) 공식_16) |
| 값은 같고 부호가 반대다 | 겹친 구간이 부호만 뒤집으면 전부 같다 | 부호를 바꾸는 곳 |
| 겹친 구간은 같고 길이가 다르다 | 겹친 구간이 전부 같고 밀림이 없는데 길이가 다르다 | 출력 샘플 수 |
| 모양은 같고 크기가 몇 배다 | 파형 유사도 99.9% 이상, 대부분의 샘플이 다르고, 크기 비가 1에서 0.001 넘게 벗어난다 | 윈도우 합, $N$으로 나누는 곳 ([03](03_지식과%20공식.md) 공식_15) |
| 거의 같다 | 파형 유사도 99.9% 이상 | 반올림, 다른 샘플의 위치 |
| 주파수별 크기는 같고 파형이 다르다 | 스펙트럼 유사도 95% 이상, 파형 유사도 90% 미만 | 스펙트럼의 허수부, 켤레, 순서 |
| 일부만 복원되었다 | 겹친 구간의 일치율 50% 이상 | 다른 샘플의 처음과 마지막 위치 |
| 복원되지 않았다 | 위의 어느 것도 아니다 | — |

위에서부터 차례로 맞춰 보고 처음 맞는 것을 낸다. 기준 값(99.9, 95, 90, 50, 0.001)은 `testvec.py` 위쪽에 상수로 적혀 있고 바꿀 수 있다.

### 4.5 힌트

결과가 아래 중 하나와 같으면 힌트가 나온다. 기대값을 바꿔 가며 **비교만** 한다.

| 결과의 모습 | 힌트 | 먼저 볼 곳 |
|---|---|---|
| 기대값의 512배 또는 1/512배 | 크기가 기대값의 N배(1/N배)다 | $N$으로 나누는 곳 ([03](03_지식과%20공식.md) 공식_3, 공식_8) |
| 허수부의 부호만 반대 | 허수부의 부호가 반대다 | 회전 인자 지수의 부호 ([03](03_지식과%20공식.md) 공식_2) |
| k번 자리에 N−k번 자리의 값 | 순서가 뒤집혀 있다 | 같음. IFFT에서는 FFT를 그대로 쓴 경우에도 나온다 |
| 모든 자리가 같은 배수 | 모든 자리가 기대값의 몇 배다 | 곱하거나 나누는 상수 |
| 전부 0 | 결과가 전부 0이다 | 결과 리스트에 값을 넣는 곳 |
| `nan`, `inf` 포함 | 결과에 nan(inf)이 있다 | 0으로 나누는 곳 |
| 길이가 256 또는 257 | 절반만 돌려주고 있다 | 돌려주는 개수 |
| 윈도우가 다름 | 분모가 511인지 확인한다 | [03](03_지식과%20공식.md) 공식_9 |
| 복원율 비교에서 다른 샘플의 값이 −32768 또는 32767 | 값이 너무 커서 잘렸을 수 있다 | 윈도우 합으로 나누는 곳 ([03](03_지식과%20공식.md) 공식_15) |

실수 입력의 스펙트럼에서는 "허수부의 부호가 반대"와 "순서가 뒤집혀 있다"가 같은 말이어서([08](08_참고%20공식.md) 참고_1) 두 힌트가 함께 나온다.

힌트가 없을 때도 있다. 비트 반전을 빼먹은 경우가 그렇다 — 결과가 기대값과 단순한 관계가 아니다(검산 출력 2번의 시험 4).

### 4.6 그 밖의 실패

| 출력 | 뜻 |
|---|---|
| 결과가 None 이다 | 함수가 `return`으로 값을 돌려주지 않았다 |
| 길이가 다르다 | 기대한 개수와 돌려준 개수가 다르다 |
| 함수를 실행하다가 오류가 났다 | 함수 안에서 오류가 났다. 아래에 Traceback이 이어진다. 읽는 법은 [05](05_Python%20문법%20길잡이.md) §9 |
| N번 자리의 값을 숫자로 읽을 수 없다 | 결과 리스트에 숫자가 아닌 것이 들어 있다 |
| [오류] 파일이 없다 | `compare_wav`에 준 경로에 파일이 없다 |
| [오류] WAV 를 읽지 못했다 | WAV가 아니거나 16bit가 아니다 |

## 5. 허용 오차

테스트 벡터 비교는 차이가 `abs_tol + rel_tol × |기대값|` 이하이면 같다고 본다.

| 묶음 | `abs_tol` | `rel_tol` |
|---|---|---|
| FFT, 분석 | 1e-5 | 1e-9 |
| IFFT | 1e-6 | 1e-9 |
| 윈도우 곱 | 1e-8 | 1e-9 |
| 윈도우 | 1e-12 | 0 |

정한 근거: 올바른 구현의 계산 오차보다 충분히 크고, 잘못된 구현의 차이보다 충분히 작게 잡았다.

| 구현 | 기준값과의 가장 큰 차이 |
|---|---|
| radix-2 FFT (FFT, 분석 묶음) | 5.7e-10 |
| 정의식 DFT (같은 묶음) | 4.4e-07 |
| IFFT (FFT를 이용한 역변환) | 2.2e-11 |
| 정의식 역 DFT (IFFT 묶음) | 5.4e-09 |
| 윈도우 (수식 계산) | 4.4e-16 |
| 윈도우 곱 | 1.1e-11 |

근거: [첨부_이력_테스트 벡터 검산 출력.txt](../tasks/가이드/20260928_1728_pr-guide-and-setup/첨부_이력_테스트%20벡터%20검산%20출력.txt) 대조_1 ~ 대조_3과 5번(문서 예시 실행). 정의식 DFT와 정의식 역 DFT도 각 묶음을 통과한다.

`tv.compare`를 직접 부를 때는 `abs_tol=`, `rel_tol=`로 바꿀 수 있다. 주지 않으면 1e-5와 1e-9다.

복원율 비교(`compare_wav`, `compare_samples`)에서 일치를 셀 때는 허용 오차가 없다. 값이 완전히 같아야 일치다. `compare_samples`만 `tol=`로 허용 차이를 줄 수 있다. 파형 유사도와 스펙트럼 유사도는 일치 여부가 아니라 닮은 정도를 재므로 작은 오차에는 거의 줄지 않는다. 샘플마다 −1, 0, 1 중 하나를 더한 신호는 복원율 34.35%, 파형 유사도 100.0000%였다.

## 6. 알아 둘 것

| 항목 | 내용 |
|---|---|
| 규약 | 기대값은 $1/N$을 **역변환에만** 두는 규약으로 계산했다 ([03](03_지식과%20공식.md) §3) |
| 입력의 종류 | 샘플 입력은 정수(`int`) 리스트다. 스펙트럼 입력은 복소수(`complex`) 리스트다 |
| 스펙트럼의 개수 | 512개 전부다. 앞의 257개만 돌려주는 구현은 길이가 달라 실패한다 |
| 결과의 종류 | 실수, 복소수, numpy 배열 모두 받는다. IFFT 결과는 복소수여도 되고 실수부만이어도 된다 |
| 8점 묶음 | 길이를 512로 고정한 구현에는 쓰지 않는다 |
| 입력 보호 | `check_function`은 입력의 **복사본**을 넘긴다. 함수가 입력을 고쳐도 벡터는 그대로다. `get_case`로 꺼낸 `case["input"]`은 원본이므로 고치지 않는다 |
| 프레임 순서 | 윈도우 곱과 분석 묶음은 입력 리스트의 0번이 윈도우의 0번과 곱해진다 |
| `compare_wav`의 WAV 읽기 | `testvec.py` 안에 WAV를 읽는 코드가 들어 있다. 단계_1에서 직접 만든 읽기 함수와는 별개다 |
| 파일 비교가 쓰는 라이브러리 | 표준 라이브러리 `filecmp`의 `filecmp.cmp(경로1, 경로2, shallow=False)`. 설치할 것은 없다 |
| `shallow=False`로 둔 까닭 | 기본값 `shallow=True`는 파일의 종류, 크기, 수정 시각이 같으면 내용을 읽지 않고 같다고 본다(Python 문서). 크기와 수정 시각이 같고 내용이 다른 두 파일에서 `shallow=True`는 `True`를, `shallow=False`는 `False`를 냈다(검산 출력 7번의 파일_10) |
| 파일은 다른데 샘플이 같았던 경우 | 시험한 것은 둘이다. 헤더의 샘플링 주파수가 다른 파일, 샘플 뒤에 LIST 덩어리가 붙은 파일(크기 16,044바이트와 16,072바이트) |
| 복원율 비교가 쓰는 라이브러리 | numpy. 밀림을 찾을 때와 스펙트럼 유사도를 잴 때 numpy의 FFT와 윈도우(`np.fft`, `np.hanning`)를 부른다. 검증용이며 직접 만드는 FFT와는 별개다 |
| 밀림을 찾는 방법 | 두 신호를 어긋나게 겹쳐 가며 닮은 정도(상관)를 구해 후보 50개를 고르고, 후보마다 실제로 비교해 가장 잘 맞는 것을 고른다 |
| 주기가 있는 신호 | 1000 Hz 사인파는 16샘플마다 되풀이된다. 496샘플(16 × 31) 밀린 것과 앞의 496샘플이 비어 있는 것이 구별되지 않는다. 이때는 겹친 구간이 전부 같아지는 쪽(밀림 496)으로 판정한다 |
| 걸리는 시간 | 10초 분량(160,000샘플)을 비교하는 데 이 PC에서 0.30초. 파일 비교(1차)만은 0.002초 |
