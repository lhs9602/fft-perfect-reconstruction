# 프로젝트 구성과 실행 환경

**TL;DR**: 이 프로젝트는 전용 가상환경 `.venv`(Python 3.11.0, numpy 2.4.6, matplotlib 3.11.2, pytest 9.1.1)를 쓴다. 가상환경을 켜고 → `src/main.py`에 코드를 쓰고 → `python src\main.py`로 실행하고 → `python -m pytest`로 시험한다. 터미널은 **명령 프롬프트**를 쓴다(이 PC의 PowerShell로는 켜지지 않는다).

## 2. 가상환경

가상환경은 **이 프로젝트만 쓰는 Python과 패키지 묶음**이다. `.venv/` 폴더 안에 Python 실행 파일과 설치한 패키지가 따로 들어 있다. PC 전체에 설치된 Python(전역)의 패키지와 섞이지 않는다.

| 항목 | 값 | 확인한 방법 |
|---|---|---|
| 만든 명령 | `python -m venv .venv` | 2026-09-28 실행 |
| Python | 3.11.0 | `.venv\Scripts\python.exe --version` 출력 |
| pip | 22.3 | `.venv\Scripts\python.exe -m pip --version` 출력 |
| 전역 Python의 위치 | `C:\Users\todoc\AppData\Local\Programs\Python\Python311\python.exe` | `where python` 출력 |

만드는 명령의 형식은 Python 문서 "venv — Creation of virtual environments"에 있다.

### 2.1 가상 머신(VM)이 아니다

이름은 비슷하지만 운영체제를 따로 띄우는 가상 머신과는 다른 것이다. Python의 가상환경은 **폴더 하나**다.

| 항목 | 내용 | 근거 |
|---|---|---|
| 실체 | 프로젝트 안의 `.venv` 폴더. 이 PC에서 164 MB | 폴더 크기 확인 (2026-09-29) |
| 들어 있는 것 | `Scripts\python.exe`, `Scripts\activate.bat`, `Lib\site-packages\`(설치한 패키지), `pyvenv.cfg` | 폴더 목록 |
| 전역 Python과의 관계 | `pyvenv.cfg`의 `home`이 전역 Python 폴더(`C:\Users\todoc\AppData\Local\Programs\Python\Python311`)를 가리킨다 | 파일 내용. Python 문서 venv는 이 파일에 "만들 때 쓴 Python 설치를 가리키는 `home` 키"가 들어간다고 적는다 |
| "켠다"의 뜻 | 그 터미널의 `PATH` 맨 앞에 `.venv\Scripts`를 넣는다. 그래서 `python`이라고 치면 가상환경의 Python이 돈다 | Python 문서 venv. 켠 뒤 `PATH`의 앞부분이 `D:\Claude\projects\fft-perfect-reconstruction\.venv\Scripts;`로 시작하는 것을 확인 |
| 꼭 켜야 하는가 | 아니다. 가상환경의 Python 경로를 직접 적어도 된다 (§3.5) | Python 문서 venv |
| 지워도 되는가 | 된다. 다시 만들 수 있는 것으로 본다. 프로젝트의 코드는 이 폴더에 넣지 않는다 | Python 문서 venv |

쓰는 까닭은 **패키지를 프로젝트마다 따로 두기 위해서**다. Python 문서는 가상환경이 "저마다 독립된 패키지 묶음"을 갖는다고 적는다.

| 어디의 Python | numpy | matplotlib | pytest |
|---|---|---|---|
| 가상환경 (`.venv`) | 2.4.6 | 3.11.2 | 9.1.1 |
| 전역 | 2.4.6 | 3.11.2 | **없다** |

2026-09-29에 확인한 값이다. 전역 Python으로 `python -m pytest`를 실행하면 `No module named pytest`가 나오는 것이 이 때문이다.

## 3. 가상환경 켜고 끄기

"켠다"는 것은 그 터미널에서 `python`이라고 쳤을 때 **가상환경의 Python**이 돌도록 하는 것이다. 터미널을 새로 열 때마다 다시 켠다.

### 3.1 켜는 명령

프로젝트 폴더(`D:\Claude\projects\fft-perfect-reconstruction`)에서 실행한다. 명령 프롬프트에서 다른 드라이브(C:)에 있다가 옮겨 올 때는 `cd`에 `/d`를 붙인다. 붙이지 않으면 폴더가 바뀌지 않는다(2026-09-29 확인).

```bat
cd /d D:\Claude\projects\fft-perfect-reconstruction
```

| 터미널 | 명령 | 이 PC에서의 결과 (2026-09-29) |
|---|---|---|
| 명령 프롬프트 (cmd) | `.venv\Scripts\activate.bat` | 켜진다 |
| Git Bash | `source .venv/Scripts/activate` | 켜진다 |
| PowerShell | `.venv\Scripts\Activate.ps1` | **켜지지 않는다.** 실행 정책 때문이다 (§3.4) |

명령의 형식은 Python 문서 venv에 있다. 켜지면 프롬프트 앞에 `(.venv)`가 붙는다.

> [!IMPORTANT]
> 이 PC에서는 **명령 프롬프트(cmd)** 를 쓰는 것이 가장 간단하다. 설정을 바꿀 것이 없다.

### 3.2 켜졌는지 확인

명령 프롬프트(cmd)와 Git Bash:

```bat
where python
```

```text
D:\Claude\projects\fft-perfect-reconstruction\.venv\Scripts\python.exe
C:\Users\todoc\AppData\Local\Programs\Python\Python311\python.exe
C:\Users\todoc\AppData\Local\Microsoft\WindowsApps\python.exe
```

**첫 줄**이 실제로 도는 Python이다. 첫 줄에 `.venv`가 들어 있으면 켜진 것이다.

PowerShell:

```powershell
(Get-Command python).Source
```

```text
D:\Claude\projects\fft-perfect-reconstruction\.venv\Scripts\python.exe
```

> [!WARNING]
> PowerShell에서 `where python`은 **아무것도 출력하지 않는다.** PowerShell의 `where`는 `Where-Object`의 별칭이어서 다른 일을 한다(`Get-Alias where`로 확인). PowerShell에서는 위 명령이나 `where.exe python`을 쓴다.

어느 터미널인지는 프롬프트로 안다.

| 프롬프트의 모습 | 터미널 |
|---|---|
| `PS D:\Claude\projects\fft-perfect-reconstruction>` | PowerShell |
| `D:\Claude\projects\fft-perfect-reconstruction>` | 명령 프롬프트 (cmd) |
| `(.venv) D:\Claude\projects\fft-perfect-reconstruction>` | 명령 프롬프트, 가상환경이 켜진 상태 |

> [!WARNING]
> **버전만으로는 알 수 없다.** 이 PC는 전역 Python도 3.11.0이어서, 가상환경이 켜지지 않았어도 `python --version`은 똑같이 `Python 3.11.0`을 낸다. 반드시 **경로**로 확인한다. 켜지지 않은 채 `python -m pytest`를 실행하면 `No module named pytest`가 나온다 — 전역 Python에는 pytest가 없다(2026-09-29 확인).

> [!NOTE]
> 가상환경을 켠 상태에서도 Python이 내는 **오류 메시지**에는 전역 Python의 경로(`...\Python311\python.exe`)가 찍히는 것을 확인했다(2026-09-29). 같은 상태에서 `(Get-Command python).Source`와 `sys.prefix`는 `.venv`를 가리켰다. 켜졌는지는 위 명령으로 판단한다.


### 3.4 PowerShell에서 켜지지 않을 때

이 PC에서 새 PowerShell 창을 열어 켜는 명령을 실행하면 아래 오류가 난다(2026-09-29 확인).

```text
& : 이 시스템에서 스크립트를 실행할 수 없으므로 D:\Claude\projects\fft-perfect-reconstruction\.venv\Scripts\Activate.ps1
파일을 로드할 수 없습니다. 자세한 내용은 about_Execution_Policies(https://go.microsoft.com/fwlink/?LinkID=135170)를
참조하십시오.
    + CategoryInfo          : 보안 오류: (:) [], PSSecurityException
    + FullyQualifiedErrorId : UnauthorizedAccess
```

| 확인한 것 | 값 |
|---|---|
| `Get-ExecutionPolicy -List` | 다섯 범위 모두 `Undefined` |
| `Get-ExecutionPolicy` (실제로 적용되는 값) | `Restricted` |
| 오류 뒤의 `python` | 전역 Python (`...\Python311\python.exe`) |

설정을 바꾸지 않고 쓰는 방법:

| 방법 | 내용 |
|---|---|
| PowerShell에서 `PATH`를 직접 고친다 | 아래 한 줄을 친다. 그 터미널에서는 `python`이 가상환경의 Python이 된다 |
| 명령 프롬프트를 쓴다 | `.venv\Scripts\activate.bat` |
| PowerShell 창 안에서 명령 프롬프트로 바꾼다 | `cmd`라고 치면 같은 창이 명령 프롬프트가 된다. 그 뒤 `.venv\Scripts\activate.bat`. 되돌아갈 때는 `exit`. PowerShell 안에서 연 명령 프롬프트에서 가상환경이 켜지는 것을 확인했다(2026-09-29) |
| Git Bash를 쓴다 | `source .venv/Scripts/activate` |
| 켜지 않고 쓴다 | `python` 자리에 `.venv\Scripts\python.exe`를 적는다 (§3.5). PowerShell에서도 된다 |

PowerShell에서 `PATH`를 직접 고치는 한 줄. 프로젝트 폴더에서 친다.

```powershell
$env:PATH = "$PWD\.venv\Scripts;" + $env:PATH
```

"켠다"는 것이 `PATH` 맨 앞에 `.venv\Scripts`를 넣는 일이므로(§2.1) 그 일을 손으로 하는 것이다. 스크립트 파일을 실행하지 않으므로 실행 정책에 막히지 않는다. 실행 정책이 `Restricted`인 새 PowerShell 창에서 이 줄을 친 뒤 `(Get-Command python).Source`가 `.venv\Scripts\python.exe`를, `python -m pytest --version`이 `pytest 9.1.1`을 냈다(2026-09-29). 프롬프트에 `(.venv)`는 붙지 않는다. 터미널을 새로 열면 다시 쳐야 한다.

설정을 바꾸는 방법: Python 문서는 Windows에서 `Activate.ps1`을 쓰려면 사용자의 실행 정책을 바꿔야 할 수 있다고 적고, 아래 명령을 보여 준다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

> [!WARNING]
> 이 명령은 **PC의 보안 설정**을 바꾼다. 필요하면 직접 판단해 실행한다. Claude는 이 설정을 바꾸지 않았다.

### 3.5 켜지 않고 쓰기

Python 문서는 가상환경을 꼭 켜야 하는 것은 아니며 그 환경의 Python 경로를 직접 적어도 된다고 적는다.

```powershell
.venv\Scripts\python.exe --version
```

WAV 입출력에 쓰는 `wave`, 수학 함수 `math`와 `cmath`, 시간 측정 `time`은 Python에 들어 있는 표준 라이브러리여서 설치할 것이 없다.

### 4.2 `requirements.txt`

필요한 패키지와 버전을 적어 둔 파일이다. 다른 PC에서 같은 환경을 만들 때 쓴다.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4.3 패키지를 더 설치할 때

가상환경을 켠 상태에서 설치하고, `requirements.txt`에 한 줄을 더한다.

```powershell
python -m pip install 패키지이름
python -m pip freeze
```

`pip freeze`는 설치된 패키지와 버전을 모두 보여 준다.

> [!IMPORTANT]
> 가상환경을 **켜지 않은 채** `pip install`을 하면 전역 Python에 설치된다. 설치 전에 §3.2로 확인한다.


| 알아 둘 것 | 설명 | 근거 |

## 6. 시험하기와 `import`

### 6.1 실행

```powershell
python -m pytest
```

| 명령 | 뜻 |
|---|---|
| `python -m pytest` | `tests/`의 시험을 모두 돌린다 |
| `python -m pytest -v` | 시험 이름을 하나씩 보여 준다 |
| `python -m pytest tests\test_main.py` | 그 파일만 돌린다 |
| `python -m pytest -k 이름일부` | 이름에 그 글자가 든 시험만 돌린다 |

### 6.2 `pytest.ini`

```ini
[pytest]
pythonpath = src
testpaths = tests
```

| 줄 | 하는 일 |
|---|---|
| `pythonpath = src` | 시험을 돌릴 때 `src/`를 모듈 검색 경로에 넣는다. 그래서 `tests/`의 파일이 `src/`의 모듈을 이름만으로 `import`할 수 있다 |
| `testpaths = tests` | 시험을 찾을 폴더를 `tests/`로 정한다 |

근거: 같은 설정으로 임시 폴더에서 시험 2건이 통과했다([첨부](../tasks/가이드/20260928_1728_pr-guide-and-setup/첨부_이력_문법%20예시%20실행%20출력.txt)의 pytest 실행 출력, `configfile: pytest.ini`, `testpaths: tests`).

### 6.3 시험 파일의 규칙

| 규칙 | 예 |
|---|---|
| 파일 이름은 `test_`로 시작한다 | `tests/test_main.py` |
| 함수 이름은 `test_`로 시작한다 | `def test_impulse():` |
| 확인은 `assert`로 한다 | [05_Python 문법 길잡이.md](05_Python%20문법%20길잡이.md) §21 |

지금은 `tests/test_main.py`에 시험 7개(`test_main_exists`와 단계_3, 단계_4 시험 6개), `tests/test_dft.py`에 단계_2 시험 4개가 들어 있다. 단계_3, 단계_4 시험 6개는 FFT와 IFFT를 채우기 전까지 실패한다(`6 failed, 5 passed`, 2026-09-30 실행 확인). 단계_2 시험은 2026-09-30 `test_main.py`에서 옮겼다.

### 7.2 ffmpeg의 옵션과 명령

ffmpeg 문서에 있는 옵션:

| 옵션 | 문서의 설명 |
|---|---|
| `-i url` | 입력 파일 |
| `-ar freq` | 오디오 샘플링 주파수를 정한다 |
| `-ac channels` | 오디오 채널 수를 정한다 |
| `-y` | 출력 파일을 묻지 않고 덮어쓴다 |

위 옵션으로 만든 명령의 모양이다. `input.mp3`는 바꿀 파일의 이름이다.

```bat
ffmpeg -i input.mp3 -ar 16000 -ac 1 data\input\speech.wav
```

예시용 파일이 필요하면 Windows에 들어 있는 소리를 바꿔 쓸 수 있다. 프로젝트 폴더에서 실행한다.

```bat
ffmpeg -i "C:\Windows\Media\Alarm01.wav" -ar 16000 -ac 1 data\input\alarm.wav
```

`Alarm01.wav`는 22050 Hz 스테레오, 122,868프레임(약 5.6초)이다(2026-09-29 `wave`로 읽음). Windows에 딸린 소리이므로 시험에만 쓰고 다른 곳에 올리지 않는다.

같은 명령을 임시 폴더로 출력해 확인한 결과(2026-09-29):

| 항목 | 값 |
|---|---|
| ffmpeg가 알린 출력 형식 | `pcm_s16le`, 16000 Hz, mono, s16 |
| `wave` 모듈로 읽은 값 | 채널 1, 샘플 폭 2바이트, 16000 Hz, 89,156프레임, 5.572초 |
| 샘플의 범위 | −11006 ~ 9501 |
| 파일 크기 | 178,390바이트 |
| 헤더의 길이 | **78바이트**. `fmt `와 `data` 사이에 `LIST` 청크(34바이트, 내용은 만든 프로그램의 이름 `Lavf63.1.101`)가 들어 있다 |

입력 조건(16 kHz, 모노, 16bit)에 맞는다. `-ar`, `-ac` 말고 비트 수를 정하는 옵션은 주지 않았다.

> [!NOTE]
> ffmpeg가 만든 파일은 헤더가 44바이트가 아니다([07](07_WAV%20파일.md) §4의 경고가 실제로 일어나는 예다). 이 파일을 입력으로 쓰고 복원한 출력을 `wave` 모듈로 저장하면 **샘플이 전부 같아도 두 파일의 바이트는 다르다.** `tv.compare_wav`는 1차(파일 비교)에서 "다르다", 2차에서 "완전 복원"을 내고 "샘플이 아닌 부분이 다르다"고 알린다([06](06_테스트%20벡터%20사용법.md) §3.6).

### 7.3 한 주파수만 있는 파일 (사인파)

ffmpeg로 만든다. 식은 [08](08_참고%20공식.md) 참고_10이다. 문서의 기대값은 아래 첫 명령으로 만든 `sine_1k.wav`(1000 Hz, 진폭 10000) 기준이다.

**진폭까지 정하는 명령.** 프로젝트 폴더에서 실행한다. 1000 Hz, 진폭 10000, 1초, 16 kHz다.

```bat
ffmpeg -f lavfi -i "aevalsrc=0.30517578125*sin(2*PI*1000*t):s=16000:d=1" -c:a pcm_s16le data\input\sine_1k.wav
```

| 부분 | 뜻 | 바꾸는 법 |
|---|---|---|
| `-f lavfi` | 입력이 파일이 아니라 ffmpeg가 만들어 내는 신호다 | — |
| `aevalsrc=식` | 식으로 계산한 소리를 만든다 | — |
| `0.30517578125` | 진폭. 16bit 값 10000을 32768로 나눈 것 | 진폭 ÷ 32768. 예: 20000이면 0.6103515625 |
| `sin(2*PI*1000*t)` | 1000 Hz 사인파. `t`는 시간(초) | `1000`을 원하는 주파수로. 2 kHz면 `2000` |
| `s=16000` | 샘플링 주파수 | — |
| `d=1` | 길이(초) | 3초면 `d=3` |
| `-c:a pcm_s16le` | 16bit PCM으로 저장한다 | — |

**간단한 명령.** 진폭을 정하지 않는다.

```bat
ffmpeg -f lavfi -i "sine=frequency=2000:sample_rate=16000:duration=1" data\input\sine_2k_small.wav
```

확인한 결과(2026-09-29, 임시 폴더에 만들어 `wave`로 읽음):

| 명령 | 최소 ~ 최대 | 앞 5개 | 참고_10의 값(진폭 10000)과 같은 샘플 |
|---|---|---|---|
| `aevalsrc`, 1000 Hz | −10000 ~ 10000 | 0, 3827, 7071, 9239, 10000 | **16,000개 전부** |
| `aevalsrc`, 2000 Hz | −10000 ~ 10000 | 0, 7071, 10000, 7071, 0 | 16,000개 전부 |
| `sine`, 1000 Hz | −4095 ~ 4095 | 0, 1567, 2896, 3783, 4095 | 크기가 다르다 |
| `sine`, 2000 Hz | −4095 ~ 4095 | 0, 2896, 4095, 2896, 0 | 크기가 다르다 |

| 알아 둘 것 | 내용 |
|---|---|
| 형식 | 넷 다 채널 1, 16bit, 16000 Hz, 16,000샘플 |
| 파일 크기 | 32,078바이트. `wave` 모듈로 쓴 파일(32,044바이트)보다 34바이트 크다. `LIST` 청크 때문이다(§7.2) |
| 단계_1의 출력과 맞춰 보기 | `sine_1k.wav`와 단계_1이 다시 쓴 `data/output/sine_1k.wav`를 `tv.compare_wav`에 넣으면 샘플이 전부 같다. 파일 비교(1차)는 헤더가 달라 "다르다"가 나온다 |
| 주파수의 한계 | 샘플링 주파수의 절반(8000 Hz)보다 낮아야 한다 ([02](02_1.5%20FFT%20경로%20사양.md) §3.2) |

근거: 기대값 검산 기대값_19. 옵션의 이름은 설치된 ffmpeg의 도움말(`ffmpeg -h filter=sine`, `ffmpeg -h filter=aevalsrc`)에서 확인했다.

준비한 파일은 `data/input/`에 둔다.

| | `window size` | 스펙트로그램을 만들 때의 FFT 크기. 256, 512, 1024, 2048, 4096, 8192, 16384, 32768 중에서 고른다 |
| | `frequency scale` | 세로축(주파수)의 눈금. `Linear`, `Log`, `Mel` |
| | `mel filter num` | `Mel`을 골랐을 때 쓰는 필터의 수 |
| | `frequency range` _ Hz ~ _ Hz | 그릴 주파수 범위. 0부터 샘플링 주파수의 절반까지 |
| | `spectrogram amplitude range` _ dB ~ 0 dB | 색으로 나타낼 크기의 범위. 가장 큰 값을 0 dB로 두고 거기서 몇 dB 아래까지 보일지 |
| | `color` | 크기와 색의 대응을 보여 주는 띠 |

`easyCut` 칸 — 화면의 설명은 "Cut the currently selected range and save it to a wav file (experimental)"이다.

| 항목 | 뜻 |
|---|---|
| `filename` _ `.wav` | 저장할 파일의 이름 |
| `cut` | 지금 고른 구간(그래프에서 끌어 고른 시간 범위)을 잘라 저장한다 |

| 이 프로젝트에 맞춘 값 | 까닭 |
|---|---|
| `window size` 512 | 이 프로젝트의 FFT 크기와 같다. 칸 간격이 31.25 Hz가 된다 |
| `frequency scale` Linear | bin 번호와 주파수가 비례한다([08](08_참고%20공식.md) 참고_2). 1000 Hz가 8000 Hz의 8분의 1 높이에 그려진다 |
| `frequency range` 0 ~ 8000 Hz | 16 kHz 파일이 담는 주파수 전체 |

> [!NOTE]
> 확장은 샘플을 실수로 바꿔 다룬다. 화면 코드에서 샘플을 32비트 실수 배열에 담고, `easyCut`으로 저장할 때 값을 −1 ~ 1로 자른 뒤 16bit로 쓰는 것을 읽었다. 그래서 파형의 세로축은 16bit 정수가 아니라 **−1 ~ 1의 분수**로 그려질 것으로 본다(해석). 진폭 10000인 사인파라면 0.305쯤이다([07](07_WAV%20파일.md) 변환_2). `easyCut`으로 저장한 파일은 헤더가 44바이트다(화면 코드의 WAV 쓰기에서 읽음). 화면을 직접 보고 확인한 것은 아니다.

| 이 프로젝트에서의 쓰임 | 볼 것 |
|---|---|
| 사인파 파일(`sine_1k.wav`) | 스펙트로그램에 1000 Hz 자리의 가로줄 하나가 보여야 한다 (해석) |
| 원본과 복원을 나란히 | 두 파일을 열어 파형과 스펙트로그램이 같은지 본다. 값이 완전히 같은지는 눈으로 알 수 없으므로 `tv.compare_wav`로 확인한다 |

### 8.2 줄 정리 (yapf)와 검사 (Ruff)

**줄 정리는 yapf 확장**, **검사(밑줄)는 Ruff 확장**이 한다(2026-09-30 사용자 결정). yapf는 띄어쓰기를 규칙대로 맞추고, 줄 끝 주석을 같은 열에 나란히 세운다.

| 할 일 | 단축키 |
|---|---|
| 파일 전체 정리 | `Shift+Alt+F` (저장할 때도 한다) |
| 선택한 줄만 정리 | 줄을 선택하고 `Ctrl+K` 다음 `Ctrl+F` |

VS Code 설정:

1. 확장에서 `yapf`(EeyoreLee, `eeyore.yapf`)를 설치한다. yapf 0.43.0이 들어 있다
2. `settings.json`의 `"[python]"`에서 `"editor.defaultFormatter"`를 `"eeyore.yapf"`로 둔다. `"editor.formatOnSave": true`는 그대로 둔다
3. `main.py`를 열고 `Shift+Alt+F`로 주석이 한 열에 서는지 본다. 설정 파일을 못 찾으면 `"yapf.args": ["--style", "D:/Claude/projects/fft-perfect-reconstruction/.style.yapf"]`를 더한다(확장 설명의 `yapf.args` 예와 같은 모양)

| 알아 둘 것 | 내용 | 근거 |
|---|---|---|
| 설정 파일 | 프로젝트 폴더의 `.style.yapf`. PEP 8 바탕, 줄 길이 1000, 주석 열 `30, 40, …, 160` | yapf README (`SPACES_BEFORE_COMMENT`, 설정 파일 찾는 순서) |
| 설정 파일은 ASCII만 | yapf가 이 파일을 Windows 기본 인코딩(cp949)으로 읽는다. 한글 주석을 넣으면 `UnicodeDecodeError`로 멈춘다. 그래서 주석을 영어로 적었다 | 2026-09-30 yapf 0.43.0으로 사본에 돌려 봄 |
| 주석 열 맞춤 | 붙어 있는 줄들의 끝 주석이, 그 줄들 중 가장 긴 코드보다 뒤에 있는 첫 열(30, 40, …)에 선다 | yapf README, 같은 날 사본 |
| 주석만 있는 줄 | 끝에 주석이 달린 줄 **바로 다음**의 주석만 있는 줄은 주석 열로 밀려난다. 그 앞에 **빈 줄**을 하나 둔다 | 같은 날 사본 (빈 줄을 두면 밀리지 않음) |
| 한글이 든 코드 줄 | yapf는 글자 수로 센다. 코드에 한글 문자열이 있는 줄(`print("길이:" …)`)은 화면에서 주석이 한글 폭만큼 어긋나 보인다 | 같은 날 사본 |
| 줄 길이 | 주석만 줄 제한에서 빼는 설정은 Ruff와 yapf 모두 없다. 둘 다 끝 주석까지 넣어 세고, 넘으면 `for k in range(` / `N` / `):`처럼 코드를 쪼갠다. 그래서 줄 길이를 1000으로 두어 사실상 제한을 없앴다(`.style.yapf`, `ruff.toml`) | `ruff rule E501`, 같은 날 두 도구를 줄 길이 60으로 사본에 돌려 봄 |
| Ruff의 줄 정리 | 쓰지 않는다. Ruff는 줄 끝 주석 앞을 늘 두 칸으로 바꾸고, 칸 수를 정하는 설정이 없다 | `ruff config format`(설정 9개), 같은 날 사본 |
| 검사 규칙 | `ruff.toml`의 `[lint]`에 `E`, `F`, `UP`, `B`, `SIM`, `I`를 켰다. Ruff 문서가 많이 쓰는 규칙을 켜는 예로 드는 묶음이다. 걸린 곳은 편집기에 밑줄로 보인다. `N`(이름 규칙)은 켜지 않았다. 식의 기호대로 쓴 `N`, `X`를 잘못으로 본다 | Ruff 문서 linter 설정 예. 2026-09-30 `ruff check`로 확인 |
| 저장할 때 고치기 (`source.fixAll`) | 켜지 않는다. 안 쓰는 import를 지운다. `testvec.py`의 `from testvec_data import ...`는 시험 파일이 `tv.FFT_CASES`처럼 쓰려고 옮겨 둔 것인데, Ruff는 안 쓰는 import(`F401`)로 본다 | 같은 날 `ruff check` 결과 |
