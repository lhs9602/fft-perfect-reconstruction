# WAV 파일

**TL;DR**: WAV는 헤더 뒤에 16bit 정수 샘플을 시간 순서대로 적은 파일이다. 규격, Python의 `wave` 모듈, 실제 파일의 바이트, 읽고 쓸 때의 변환 규칙(`변환_1`), 1.5 샘플 형식으로 바꾸는 식(`변환_2`)을 담았다. 단계_1과 단계_9에서 쓴다.

## 1. WAV란

WAV는 **소리를 숫자로 적어 둔 파일**이다. 앞쪽에 "뒤의 숫자들을 어떻게 읽는가"를 적은 헤더가 있고, 그 뒤에 샘플이 시간 순서대로 놓인다. 처음 보는 경우 아래 표와 §4(실제 파일의 바이트)를 먼저 읽는다.

| 말 | 뜻 | 이 프로젝트의 값 | 근거 |
|---|---|---|---|
| 샘플 | 한 시점의 소리 크기를 적은 정수 하나 | −32768 ~ 32767 | §2 |
| 샘플링 주파수 | 1초에 샘플을 몇 개 적는가 | 16000 | 헤더의 `nSamplesPerSec`. P. Kabal은 "Sampling rate (blocks per second)"라고 적는다 |
| 샘플의 비트 수 | 샘플 하나를 몇 비트로 적는가 | 16 (2바이트) | 헤더의 `wBitsPerSample` ("Bits per sample") |
| 채널 | 함께 적은 소리의 수. 모노는 1, 스테레오는 2 | 1 | 헤더의 `nChannels`, Python 문서 `wave` |
| PCM | 형식 코드 1. 샘플 값을 압축하지 않고 그대로 적는다 | PCM | 헤더의 `wFormatTag`. `wave` 모듈은 이 형식의 파일을 `comptype='NONE'`, `compname='not compressed'`로 알려 준다([05](05_Python%20문법%20길잡이.md) §16의 출력) |
| 헤더 | 샘플 앞에 놓인 부분. 위의 값들이 적혀 있다 | 44바이트 | §4 |

이 프로젝트에서 WAV가 맡는 자리:

| 1.5 펌웨어 | 이 프로젝트 | 근거 |
|---|---|---|
| 마이크에서 온 샘플이 프레임마다 16개씩 들어온다 | WAV 파일에서 읽은 샘플을 16개씩 꺼내 같은 자리에 넣는다 | [02_1.5 FFT 경로 사양.md](02_1.5%20FFT%20경로%20사양.md) §2의 순서 1 |
| 결과를 소리로 되돌리지 않는다 | 복원한 샘플을 WAV 파일로 저장해 원본과 비교한다 | 같은 문서 §2의 순서 10 |

## 2. WAV 파일 규격

| 항목 | 내용 | 근거 |

|---|---|---|
| `wFormatTag` | 2 | PCM |
| `nChannels` | 2 | 1 |
| `nSamplesPerSec` | 4 | 16000 |
| `nAvgBytesPerSec` | 4 | — |
| `nBlockAlign` | 2 | — |
| `wBitsPerSample` | 2 | 16 |

## 3. Python의 `wave` 모듈

근거: **출처** — Python 3.11 문서 "wave — Read and write WAV files".

| 항목 | 문서의 서술 |
|---|---|
| 지원 형식 | `WAVE_FORMAT_PCM`만 지원한다. 압축은 지원하지 않는다 |
| `wave.open(file, mode)` | `'rb'`는 읽기 전용, `'wb'`는 쓰기 전용. `with` 문에 쓸 수 있고 블록이 끝나면 닫힌다 |
| `getnchannels()` | 채널 수 (모노 1, 스테레오 2) |
| `getsampwidth()` | 샘플 폭, **바이트** 단위 |
| `getframerate()` | 샘플링 주파수 |
| `getnframes()` | 오디오 프레임의 수 |
| `readframes(n)` | 최대 n개 프레임을 읽어 `bytes`로 돌려준다 |
| `setnchannels(n)`, `setsampwidth(n)`, `setframerate(n)` | 쓰기 쪽 설정 |
| `writeframes(data)` | 프레임을 쓰고 프레임 수가 맞도록 한다 |

> [!WARNING]
> **"프레임"이라는 말이 두 가지로 쓰인다.** `wave` 모듈의 프레임은 **한 시점의 샘플 묶음**(모노면 샘플 1개)이다. 이 프로젝트의 프레임은 **16샘플 묶음**이다. 모노 16 kHz 1초짜리 파일은 `wave`의 프레임으로 16,000개, 이 프로젝트의 프레임으로 1,000개다.

`wave` 문서에는 바이트 순서와 부호에 대한 서술이 없다. `readframes`가 돌려주는 `bytes`는 §2의 WAV 규격대로 읽는다 — 2바이트씩, little-endian, 부호 있는 정수.

## 4. 실제 파일의 바이트

시험용 사인파(1000 Hz, 진폭 10000, 1초, 16 kHz)를 `wave` 모듈로 저장한 파일을 바이트 단위로 읽은 것이다. 파일 크기는 32,044바이트다. 근거: 기대값 검산 기대값_16. [04_구현 가이드라인.md](04_구현%20가이드라인.md) 단계_1이 `sine_1k.wav`를 읽어 다시 쓴 `data/output/sine_1k.wav`가 이 파일과 바이트까지 같다(2026-09-29 확인).

**파일의 짜임**. WAV 파일은 "청크"라는 덩어리로 이루어진다. 청크 하나는 이름 4바이트, 크기 4바이트, 내용의 순서다(출처: P. Kabal, "Wave File Specifications").

| 덩어리 | 들어 있는 것 | 이 파일에서의 크기 |
|---|---|---|
| `RIFF` | 파일 전체를 감싼다. 안에 `WAVE`라는 표시와 아래 두 청크가 들어 있다 | 12바이트 (이름, 크기, `WAVE`) |
| `fmt ` | 형식 — 채널 수, 샘플링 주파수, 비트 수 | 24바이트 (이름, 크기, 내용 16) |
| `data` | 샘플 | 8바이트 (이름, 크기) + 샘플 32,000바이트 |

**헤더 44바이트**. 숫자는 모두 little-endian이다.

| 위치 | 항목 | 파일의 바이트 (16진수) | 읽은 값 | 뜻 |
|---|---|---|---|---|
| 0 ~ 3 | `ckID` | `52 49 46 46` | `RIFF` | 청크의 이름 |
| 4 ~ 7 | `cksize` | `24 7d 00 00` | 32036 | 이 뒤에 남은 바이트 수. 파일 크기 − 8 |
| 8 ~ 11 | `WAVEID` | `57 41 56 45` | `WAVE` | WAV 파일이라는 표시 |
| 12 ~ 15 | `ckID` | `66 6d 74 20` | `fmt ` | 청크의 이름. 끝은 빈칸이다 |
| 16 ~ 19 | `cksize` | `10 00 00 00` | 16 | 이 청크의 내용 크기 |
| 20 ~ 21 | `wFormatTag` | `01 00` | 1 | 형식 코드. 1은 PCM |
| 22 ~ 23 | `nChannels` | `01 00` | 1 | 채널 수 |
| 24 ~ 27 | `nSamplesPerSec` | `80 3e 00 00` | 16000 | 샘플링 주파수 |
| 28 ~ 31 | `nAvgBytesPerSec` | `00 7d 00 00` | 32000 | 1초에 쓰는 바이트 수 |
| 32 ~ 33 | `nBlockAlign` | `02 00` | 2 | 한 시점의 샘플 묶음이 차지하는 바이트 수 |
| 34 ~ 35 | `wBitsPerSample` | `10 00` | 16 | 샘플의 비트 수 |
| 36 ~ 39 | `ckID` | `64 61 74 61` | `data` | 청크의 이름 |
| 40 ~ 43 | `cksize` | `00 7d 00 00` | 32000 | 샘플 데이터의 바이트 수 |
| 44 ~ | 샘플 | `00 00 f3 0e 9f 1b 17 24 10 27 …` | 0, 3827, 7071, 9239, 10000, … | 2바이트에 샘플 하나 |

항목의 이름과 바이트 수는 P. Kabal의 표를 따랐다. 값은 파일에서 읽은 것이다.

**샘플이 바이트로 적히는 모양**

| 샘플 값 | 16비트로 적은 값 (16진수) | 파일에 놓인 두 바이트 |
|---|---|---|
| 0 | `0000` | `00 00` |
| 3827 | `0EF3` | `f3 0e` |
| 10000 | `2710` | `10 27` |
| −3827 | `F10D` | `0d f1` |
| −10000 | `D8F0` | `f0 d8` |

| 규칙 | 설명 | 근거 |
|---|---|---|
| little-endian | 작은 자리의 바이트가 **앞에** 온다. `0EF3`이 `f3 0e`로 적힌다 | §2, 위 표 |
| 2의 보수 | 음수는 65536을 더한 값으로 적는다. −3827 + 65536 = 61709 = `F10D` | §2, 유도 |

**크기 계산** (유도)

| 구할 것 | 식 | 이 파일 |
|---|---|---|
| 파일 크기 | 44 + 샘플 수 × 채널 수 × 2 | 44 + 16000 × 1 × 2 = 32,044바이트 |
| 1초에 쓰는 바이트 수 | 샘플링 주파수 × 채널 수 × 2 | 16000 × 1 × 2 = 32,000 |
| 길이(초) | 샘플 데이터의 바이트 수 ÷ 1초에 쓰는 바이트 수 | 32000 ÷ 32000 = 1초 |

> [!WARNING]
> **헤더가 늘 44바이트인 것은 아니다.** 위는 Python의 `wave` 모듈이 쓴 파일이다. P. Kabal의 문서에는 `fact` 청크와 `bext` 청크가 더 나오고, 샘플 뒤에 `LIST` 청크를 붙인 파일(28바이트가 더 길다)을 `wave` 모듈이 문제없이 읽는 것을 확인했다([첨부_이력_테스트 벡터 검산 출력.txt](../tasks/가이드/20260928_1728_pr-guide-and-setup/첨부_이력_테스트%20벡터%20검산%20출력.txt) 7번의 파일_5). ffmpeg로 만든 WAV는 `fmt `와 `data` 사이에 `LIST` 청크가 들어 있어 헤더가 78바이트였다(기대값 검산 기대값_18). 그래서 파일을 읽을 때 "앞의 44바이트를 건너뛴다"고 짜지 않고 `wave` 모듈에 맡긴다(§3).

**직접 보는 방법**

| 볼 것 | 방법 | 근거 |
|---|---|---|
| 바이트 | VS Code에서 파일을 오른쪽 클릭 → Open With → Hex Editor | Hex Editor 확장의 README |
| 소리, 파형 | audio-preview 확장으로 파일을 연다 | audio-preview 확장의 README |

## 5. 정수와 실수 사이

**변환_1** 정수와 실수 사이 (정의)

- **무엇인가** — WAV의 16bit 정수와 계산에 쓰는 실수 사이를 오가는 규칙이다
- **어디에 쓰는가** — 단계_1(읽은 정수를 그대로 쓴다), 단계_9(실수를 정수로 바꿔 저장한다). 2026-09-30부터 이 프로젝트는 읽을 때 **변환_2**(§6)를 쓴다. 쓸 때의 반올림과 자르기는 32768을 곱한 뒤에 이 규칙대로 한다

| 말 | 뜻 | 이 프로젝트의 값 |
|---|---|---|
| 16bit 정수 | WAV 파일에 적혀 있는 샘플 값 | −32768 ~ 32767 |
| 실수 | 계산하는 동안 쓰는 값. Python의 `float` | |
| 반올림 | 가장 가까운 정수로 바꾼다. Python에서는 `round` | |
| 자르기 | 범위를 벗어난 값을 범위의 끝 값으로 바꾼다 | −32768보다 작으면 −32768, 32767보다 크면 32767 |

| 방향 | 방법 |
|---|---|
| 읽을 때 | 16bit 정수 값을 **그대로** 실수로 쓴다. 스케일을 곱하지 않는다 |
| 쓸 때 | 실수를 가장 가까운 정수로 반올림하고, −32768 ~ 32767을 벗어나면 끝 값으로 자른다 |

도출할 식이 아니라 정한 규칙이다. 이렇게 정한 까닭:

| 규칙 | 까닭 |
|---|---|
| 읽을 때 스케일을 곱하지 않는다 | 문서의 기대값(진폭 10000 등)을 그대로 맞춰 볼 수 있다. 1.5 형식으로 바꾸려면 변환_2 |
| 쓸 때 반올림한다 | 복원이 맞으면 값이 정수에서 1e-11쯤만 벗어난다([03](03_지식과%20공식.md) §9.4). 가장 가까운 정수가 원래 값이다([08](08_참고%20공식.md) 참고_8 아래의 "0.5인 까닭") |
| 범위를 자른다 | 2바이트에 담을 수 없는 값을 바꾸면 오류가 난다 — `to_bytes`는 `OverflowError`, `struct.pack`은 `struct.error`([05](05_Python%20문법%20길잡이.md) §15) |

Python의 `round`는 정확히 0.5인 값을 **짝수 쪽으로** 보낸다(출처: Python 3.11 문서 "Built-in Types"의 `round(x[, n])` — "rounding half to even").

| 값 | `round` 결과 |
|---|---|
| 0.5 | 0 |
| 1.5 | 2 |
| 2.5 | 2 |
| −1.5 | −2 |
| 32767.6 | 32768 (범위를 벗어난다) |
| −32768.6 | −32769 (범위를 벗어난다) |

근거: 기대값 검산 기대값_6. 복원이 정확하면 반올림 전 값은 정수에서 1e-11 수준만 벗어나므로([03](03_지식과%20공식.md) §9.4) 0.5 근처의 처리 방식은 결과에 영향을 주지 않는다. 범위를 자르는 처리는 나중에 스펙트럼을 고치는 실험을 할 때 필요해진다.

## 6. 1.5의 샘플 형식으로 바꾸기

**2026-09-30부터 이 프로젝트는 이 절의 변환_2를 쓴다**(사용자 결정). 계산은 float로 하고 값의 범위만 1.5와 같은 −1 ≤ x < 1로 맞춘다. `src/main.py`의 `read_wav`가 읽은 직후 32768로 나누고, `write_wav`가 쓰기 직전 32768을 곱해 반올림하고 자른다. 그 전에는 변환_1(16bit 정수 값을 그대로 실수로 쓴다)이 기본이었고, 04의 기대값 가운데 크기 값은 그 기준이다.

**1.5의 샘플 형식** (코드에서 확인한 것)

| 사실 | 근거 (`projects/sulivan1.5/td24-18-s-ext-as/` 기준) |
|---|---|
| 워드 하나가 24비트다. 범위는 −8,388,608 ~ 8,388,607 | `Sullivan1_5__CFX/signalProcessing/definitionsForAlgorithm.h:39-40` |
| 마이크 샘플은 "CFX 24 bit 값 그대로"다 | `Sullivan1_5__CFX/systemControl/tdc_dmic_log.h:48` 주석 |
| 24비트 워드를 분수로 읽는 형식을 Q1.23(`frac24_t`)이라고 부른다 | `Sullivan1_5__CFX/signalProcessing/agc.c:287` 주석 |
| 윈도우 계수는 24비트 분수값이다 | HEAR 문서 §3.3.1.3 ([02](02_1.5%20FFT%20경로%20사양.md) §7) |

Q1.23은 24비트 정수 $v$를 $v \div 2^{23}$으로 읽는 것이다(유도: 소수점 아래가 23비트). 그래서 범위가 $-1 \le x < 1$이 된다. 가장 큰 값은 $8388607 \div 8388608 = 0.99999988$이다.

**변환_2** 16bit 정수와 1.5 형식 사이 (정의)

- **무엇인가** — WAV의 16bit 정수를 1.5 워드와 같은 **분수(−1 ≤ x < 1)** 로 바꾸는 식이다
- **어디에 쓰는가** — 단계_1에서 읽은 직후(`read_wav`)와 단계_9에서 쓰기 직전(`write_wav`)에 한 번씩

| 기호 | 뜻 | 범위 |
|---|---|---|
| $s$ | WAV의 16bit 정수 샘플 | −32768 ~ 32767 |
| $x$ | 분수로 나타낸 샘플 | −1 ≤ $x$ < 1 |
| $v$ | 24비트 정수로 나타낸 샘플. 1.5의 워드에 담기는 모양 | −8,388,608 ~ 8,388,352 |
| 32768 | $2^{15}$. 16bit 정수가 담는 가장 큰 크기 | |
| 256 | $2^{8}$. 24비트와 16비트의 차이인 8비트만큼 왼쪽으로 옮긴다 | |

| 방향 | 식 |
|---|---|
| 16bit 정수 $s$ → 분수 $x$ | $x = s \div 32768$ |
| 16bit 정수 $s$ → 24비트 정수 $v$ | $v = s \times 256$ (왼쪽으로 8비트) |
| 분수 $x$ → 16bit 정수 | $x \times 32768$을 반올림하고 −32768 ~ 32767로 자른다 |

**도출** (유도)

1. 1.5의 Q1.23은 24비트 정수 $v$를 $2^{23}$으로 나눠 읽는다(위의 설명)
2. 16bit 정수 $s$를 24비트에 담으려면 아래 8비트를 비워 두고 위로 올린다: $v = s \times 2^{8} = s \times 256$. 16진수로 보면 뒤에 `00`이 붙는다(아래 표)
3. 1에 넣으면 $x = v \div 2^{23} = s \times 2^{8} \div 2^{23} = s \div 2^{15} = s \div 32768$
4. 그래서 두 식은 같은 값을 가리킨다. 가장 작은 $s = -32768$은 $-1$, 가장 큰 $s = 32767$은 $0.99997$이 되어 $-1 \le x < 1$에 들어간다

| 16bit 정수 | 분수 | 24비트 정수 | 24비트 (16진수) |
|---|---|---|---|
| 0 | 0 | 0 | `000000` |
| 1 | 0.0000305176 | 256 | `000100` |
| 3827 | 0.1167907715 | 979,712 | `0EF300` |
| 10000 | 0.3051757812 | 2,560,000 | `271000` |
| 32767 | 0.9999694824 | 8,388,352 | `7FFF00` |
| −3827 | −0.1167907715 | −979,712 | `F10D00` |
| −32768 | −1 | −8,388,608 | `800000` |

근거: 기대값 검산 기대값_17. 16진수를 보면 16bit 값(`0EF3`) 뒤에 `00`이 붙은 모양이다.

**손실이 있는가** — 없다.

| 확인 | 결과 | 근거 |
|---|---|---|
| 16bit 값 65,536개를 모두 분수로 바꿨다가 되돌림 | 전부 같다 | 기대값 검산 기대값_17 |
| 같은 복원 절차를 정수 그대로와 분수로 각각 실행 (시험용 사인파) | 최대 오차가 둘 다 5.457e-12, 반올림 후 다른 샘플 0개 | 같음 |
| 같은 비교 (16bit 전 범위 난수 16,000개) | 최대 오차가 둘 다 2.183e-11, 반올림 후 다른 샘플 0개 | 같음 |

오차의 단위는 16bit 정수 한 눈금이다. 32768이 2의 거듭제곱이어서 나누기와 곱하기에서 값이 바뀌지 않는다(유도).

**분수로 하면 달라지는 것**

| 항목 | 달라지는가 | 내용 |
|---|---|---|
| FFT, IFFT, 윈도우, 겹쳐 더하기의 식 | 아니다 | 입력에 상수를 곱하면 결과에도 같은 상수가 곱해질 뿐이다 (유도) |
| 테스트 벡터 ([06](06_테스트%20벡터%20사용법.md)) | 아니다 | 벡터의 입력은 16bit 정수다. 함수에 그대로 넣어 비교한다 |
| 스펙트럼의 크기 | 32768분의 1이 된다 | 시험용 사인파의 프레임 31, bin 32: 1,277,512.515 → 38.986588 |
| 윈도우 합, 나누기 전의 값 ÷ 입력 | 아니다 | 비율이다 |
| 복원값과 입력의 차이 | 32768분의 1로 보인다 | 16bit 눈금으로 보려면 32768을 곱한다 |
| SNR | 아니다 | 비율이다 |
| 읽고 쓸 때의 변환 (변환_1) | 변환_2로 바뀐다 | 읽은 직후에 나누고, 쓰기 직전에 곱한다 |

> [!NOTE]
> **해석과 미확인**: 변환_2는 "WAV가 담을 수 있는 가장 큰 값"을 "1.5의 워드가 담을 수 있는 가장 큰 값"에 맞춘 것이며 이 문서에서 정한 것이다. 1.5에서 실제 마이크 신호가 24비트 범위 가운데 어느 크기로 들어오는지는 확인하지 않았다(미확인). 1.5는 이 뒤에 입력을 `>> 5` 한다([02](02_1.5%20FFT%20경로%20사양.md) §2의 순서 2). 이 프로젝트는 그 단계를 뺐다. 넣는다면 24비트 정수가 32분의 1이 되어 16bit 값의 8배가 된다(10000 → 2,560,000 → 80,000).

> [!NOTE]
> Python의 실수는 −1 ≤ x < 1 밖의 값도 그대로 담는다. 분수로 바꿔도 계산 도중에 범위를 넘는 값(예: 스펙트럼의 크기 38.99)이 잘리지 않는다. 1.5의 24비트 워드에서 범위를 넘을 때 어떻게 되는지는 확인하지 않았다(미확인).
