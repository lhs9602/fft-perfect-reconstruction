## 2. 확인되어 맞는 것 (verified)

- hanning_window 공식 세 줄은 코드와 같다. `θ = 2πi / (N - 1)` ↔ `(2 * math.pi * i) / (N - 1)`, `w[i] = 0.5 - 0.5*cos(θ)` ↔ `0.5 - 0.5 * math.cos(angle)`, 범위 `i = 0 ~ N-1` ↔ `range(N)`. θ 는 공식 줄에서 정의되고 줄 끝 주석이 코드 이름 `angle` 과 잇는다(twiddle_table 과 같은 방식).
- window_sums 공식 `W[r] = Σ w[r + q*R]` 은 `range(r, N, R)` 와 같은 항을 더한다(N 이 R 의 배수일 때 q = 0 ~ N/R - 1, 항 32개). 기호 W[r], w[i] 의 "(코드의 ...)" 도 맞다.
- apply_window 공식 `v[i] = b[i] * w[i]`, 범위, 기호 다섯 개 모두 코드와 맞고 모두 쓰인다.
- analyze 공식 `X[k] = FFT(v)[k]`, `v[i] = b[i] * w[i]` 는 `fft(apply_window(buffer, window))` 와 같다(numpy 대조 1e-14).
- restore_overlap: `b[i]` 식, 누적 줄 `added[n] += frame[i].real` ↔ `y[n] = y[n] + IFFT(X)[i] 의 실수부`, `n = (m + 1)*R - N + i` ↔ `n = (m + 1) * R - N + i`, `x[n] = y[n] / W[n % R]` ↔ `added[n] / sums[n % R]`, 범위 줄(m, i, n)은 각 반복문의 범위와 같다. 기호 N, R, L, M, m, i, b, w, X, y, W, ceil, FFT, IFFT 는 공식에서 모두 쓰이고 모두 정의되어 있다.
- 줄 끝 주석 중 다음이 코드와 정확히 맞는다. `buffer = buffer[R:] + new  # 버퍼의 앞 R 개를 버리고 뒤에 새 R 개를 붙인다`(앞 R 개 삭제, 뒤에 R 개 추가, 길이 N 유지), `new = new + [0] * (R - len(new))  # 모자란 만큼 0 을 채워 R 개로 맞춘다`, `restored.append(added[n] / sums[n % R])  # y[n] 을 위치 n % R 의 윈도우 합으로 나눠 붙인다`, `n = (m + 1) * R - N + i  # 더할 자리 (샘플 번호)`, `added[n] += frame[i].real  # 실수부를 y[n] 에 더한다`, `frame_count ... # 프레임 수 M`. 각 def 아래 한 줄 요약도 맞다.
- 문서, 절, 단계 번호, 이력, 다른 파일을 가리키는 말은 새 주석에 없다(`단계|공식_|§|문서|\.md|이력|2026|사용자|가이드` Grep 0건).
- 구현은 `numpy.fft` 를 쓰지 않는다. 복소수 값에 산술 연산자를 쓰는 곳도 없다(복소수는 `ifft`/`fft` 안과 `frame[i].real` 읽기뿐).
- main(): 활성 복원 경로는 `restore_overlap` 하나. 주석 처리된 DFT 묶음과 FFT 겹침 없음 묶음은 줄 수가 세 줄이고 풀면 동작한다(1.9).
- 테스트 주석: `길이 512 세 개`(WINDOWED_CASES, ANALYSIS_CASES 모두 512짜리 3개), `길이 512 입력 하나`(speechlike 512), `길이 812. 16 의 배수가 아니다`(812 % 16 = 12), `위치 0 ~ 15`(len 16), 윈도우 합 기대값 네 개(0, 7, 8, 15 번)는 03 §9.3 표와 같다.

### 발견 1 (오해). restore_overlap 기호 `x[n]` 이 두 값을 가리키고 어느 쪽도 코드 이름과 잇지 않았다

- 위치: `src\main.py` 286~287행, 315행
- 본문: `#     x[n] : n번째 입력 샘플값. 마지막 식에서는 되돌린 샘플값` 과 `restored = []  # 결과 x[0] ~ x[L-1] 을 담을 리스트`
- 까닭: 입력은 코드의 `samples[n]`, 되돌린 값은 `restored[n]` 이다. 규칙은 "코드 이름과 다른 기호는 (코드의 ...) 로 잇는다" 인데 `x[n]` 에는 연결이 없다(`y[n]`, `W[r]`, `b[i]` 는 연결돼 있음). 한 기호에 두 뜻을 주어 연결을 못 쓰게 된 것이다. 공식 5번째 줄 `x[n] = y[n] / W[n % R]` 은 `x` 를 입력으로 읽어도 참(y = x * W)이라 맞아 보이지만, 코드가 계산해 내놓는 값은 `restored` 다. 줄 끝 주석 `결과 x[0] ~ x[L-1]` 은 이 함수의 코드에 없는 이름 `x` 를 쓴다(ifft 에서는 `x` 가 실제 코드 이름이라 같은 문구가 맞다).
- 교체안:
  ```
  #     x[n]  : n번째 입력 샘플값 (코드의 samples[n]). 번호가 0 보다 작거나 L 이상이면 0 으로 본다
  #     xr[n] : 복원한 n번째 샘플값 (코드의 restored[n])
  ```
  공식: `xr[n] = y[n] / W[n % R]`, 기호 `n` 줄에서는 `x[n] ...` 문장을 빼고 `입력 전체에서의 샘플 번호` 만 둔다. 줄 끝 주석: `restored = []  # 결과 xr[0] ~ xr[L-1] 을 담을 리스트`.

### 발견 5 (nit). restore_overlap 공식 4번째 줄에 `0 <= n < L` 가드가 없다

- 위치: `src\main.py` 274~276행, 293~294행
- 본문: `X = FFT(b * w)`, `... IFFT(X)[i] 의 실수부,  n = ...`, `W[n % R]`
- 까닭: (가) `b * w` 는 벡터끼리의 곱으로 읽힐 수 있다(내적, 합성곱). analyze 머리말은 `v[i] = b[i] * w[i]` 로 자리별 곱을 적어 두었고 기호 `b[i]` 와도 `b` 가 맞지 않는다. (나) `%` 가 기호 줄에 풀려 있지 않다(`ceil` 은 풀려 있다). (다) 공식 줄 안에 "의 실수부" 를 한글로 섞어 `IFFT(X)[i]` 의 실수부인지 `y[n] + IFFT(X)[i]` 의 실수부인지 읽는 사람이 정해야 한다. 코드는 `.real` 이다. (라) 쉼표 뒤 공백이 두 칸이다.
- 교체안:
  ```
  #     X = FFT(v),  v[i] = b[i] * w[i]
  #     y[n] = y[n] + IFFT(X)[i].real,  n = (m + 1)*R - N + i,  0 <= n < L 일 때만
  ```
  기호에 `n % R : n 을 R 로 나눈 나머지` 한 줄, `v[i] : 윈도우를 곱한 값` 한 줄을 더한다.

## 4. 판단한 것과 하지 않은 것

- 코드와 정면으로 어긋나는 주석(이름, 부호, 범위가 틀린 것)은 찾지 못했다. 그래서 "wrong" 등급은 없다.
- `θ`, `π`, `cos` 가 hanning_window 기호 줄에 없는 점은 공식 줄이 θ 를 직접 정의하고 twiddle_table(기존 블록)이 같은 방식이어서 발견으로 올리지 않았다.
- 테스트 파일의 줄 끝 주석은 위 verified 에 적은 숫자와 의미가 모두 맞아 지적할 것이 없었다. `assert window[0] == 0` 은 정확 비교이고 `abs(window[511]) < 1e-12` 는 허용 오차 비교로 두 끝의 방식이 다르다는 점은 주석과 코드의 어긋남이 아니라 문체 차이여서 올리지 않았다(현재 값은 둘 다 정확히 0.0).
- 읽기 전용 지시에 따라 `main.py`, `test_main.py`, 프로젝트의 `src`, `tests` 는 고치지 않았다. git 은 쓰지 않았다. 확인용 실행은 모두 stdin 으로 넘긴 스크립트(파일 없음)와 임시 출력(삭제 대상)으로 했다.
