**TL;DR**: main.py 네 함수의 머리말과 줄 끝 주석을 코드와 수치 실험으로 대조했다. 공식, 부호, 범위, 예시, 곱셈 규칙은 모두 맞았다. 어긋난 곳은 없고, fft 의 E/O 정의, 갱신 전 값, N / size, dft 참조 등 모호하거나 규칙에 걸리는 11건을 제안한다.

## 1. 범위와 방법

- 대상: 스크래치 복사본 `scratchpad\hdr1\src\main.py` 54~176행 (머리말 4개 + 함수 안 줄 끝 주석). 읽기 전용, 수정 없음. git 미사용, 설치 없음.
- 보조로 `dft.py` 를 읽었으나 이번 렌즈 밖이라 판정하지 않았다 (θ 정의 방식이 같은 패턴이라는 점만 참고).
- 실행: `.venv\Scripts\python.exe -B` (바이트코드 쓰기 끔), cwd = `hdr1`, `sys.path` 에 `src` 추가. 점검 스크립트는 `scratchpad\hdr1_check_fft.py` (복사본 바깥, 임시).

## 2. 실행한 점검과 출력

| 점검 | 결과 |
|---|---|
| `bit_reverse_order(8)` | `[0, 4, 2, 6, 1, 5, 3, 7]` — 66행 줄 끝 주석의 나열과 같다 |
| 예시 N = 8, i = 3 | `order[3] = 6` (011 -> 110) — 58행 예시 참 |
| B = log2(N) | N = 1, 2, 4, 8, 16, 512 모두 `bit_count` = log2(N), 문자열 뒤집기 기준 결과와 일치 (전부 True) |
| `twiddle_table(N)` | N = 2 ~ 512 에서 길이 N/2, `exp(-2πik/N)` 와 최대 오차 0.000e+00. `twiddle_table(1) = []` |
| `table[j * (N // size)]` | N = 16, size = 2, 4, 8, 16 전부 `exp(-2πij/size)` 와 오차 0.000e+00. 쓰는 최대 인덱스 0, 4, 6, 7 (표 길이 8 미만) |
| `table[16 / 4]` | `TypeError list indices must be integers or slices, not float` |
| fft 대 직접 DFT (cmath) | 실수 입력 N = 1, 2, 4, 8, 16, 512 최대 오차 0 ~ 5.1e-12. 복소수 입력 N = 8: 3.0e-15, N = 512: 7.1e-12 |
| ifft(fft(x)) | N = 8 오차 3.3e-17, N = 512 오차 5.6e-16 (허수부 최대 4.9e-16) |
| ifft(X) 대 직접 IDFT | N = 8: 5.5e-16, N = 512: 1.0e-14 |
| ifft(X) 대 conj(FFT(conj(X)))/N | N = 8, 512 모두 오차 0.000e+00 |
| 최상위 공식 N = 8 (무작위) | `E = DFT(x[0::2])`, `O = DFT(x[1::2])` 로 `X[k] = E + W*O` 오차 8.7e-16, `X[k+4] = E - W*O` 오차 7.1e-16 |
| E/O 를 1-based 로 읽으면 | E = DFT(x[1::2]), O = DFT(x[0::2]) 로 바꿔 넣으면 오차 3.87 (틀림) |
| 단계별 재구현 (N = 16, 코드 복사본은 건드리지 않음) | 모든 단계에서 갱신 전 앞쪽/뒤쪽 절반 = 그 묶음 자신의 샘플 `x[r + m*(N/size)]` 의 짝수/홀수 위치 원소의 DFT, 갱신 후 묶음 = 그 묶음 샘플의 DFT. 전부 True |
| 묶음이 담은 입력 번호 (N = 16) | size = 4, start = 0 은 x 번호 `[0, 8, 4, 12]`, start = 4 는 `[2, 10, 6, 14]`. 즉 앞쪽 절반(E)은 x[0], x[8] 이고 입력 전체의 짝수 번호 0, 2, ..., 14 가 아니다 |
| fft 입력 보존 | `x` 불변 True, 반환은 complex 리스트 True |
| N = 6 (2 의 거듭제곱 아님) | `bit_reverse_order(6) = [0, 2, 1, 3, 0, 2]` (중복), `fft` 는 `IndexError` — "2 의 거듭제곱이어야 한다" 는 사실인 전제 조건 |

## 3. 구획별 판정

### 3.1 bit_reverse_order (54~80행)

- 머리말: B = log2(N), 범위 i = 0 ~ N-1, 예시 (N = 8, B = 3, i = 3 (011) -> 110 = 6) 모두 코드와 일치. 기호 4개 모두 공식에서 쓰이고, 공식의 B 는 기호에 있으며 "코드의 bit_count" 도 실제 이름이다.
- 줄 끝 주석 14개 (결과 리스트, 비트 수, remaining, while 조건, `// 2`, `+= 1`, 번호 i, reversed_index, value, 반복 횟수, 왼쪽 밀기 + 맨 아래 비트 붙이기, 오른쪽 밀기, append, 첫 줄 나열) 모두 변수 이름과 동작이 맞다.
- 지적 없음.

### 3.2 twiddle_table (83~99행)

- 공식 W[k] = cos(θ) - j*sin(θ), θ = 2πk / N: 코드 `angle = (2 * math.pi * k) / N`, `complex(cos, -sin)` 와 부호, 각도, 순서 일치. 범위 k = 0 ~ N/2 - 1 은 `range(N // 2)` 와 일치 (N = 1 이면 빈 표, 코드와 모순 없음).
- 줄 끝 주석: 95행 `table[0] ~ table[N/2 - 1]`, 96행 `k = 0 ~ N/2 - 1`, 97행 `번호 k 의 각도 θ (라디안)`, 98행 `W[k] = (cos(θ), -sin(θ))` 모두 코드와 맞다. "시계 방향" 은 허수축을 위쪽으로 둔 통상 관례에서 `exp(-iθ)` 와 일치한다 (관례 의존, 지적하지 않음).
- 지적: 아래 지적_11 (θ 가 기호에 없음).

### 3.3 fft (102~151행)

- 공식 `X[k] = E[k] + W[k]*O[k]`, `X[k + N/2] = E[k] - W[k]*O[k]`, 범위: 수치로 참 (최상위 오차 1e-15).
- "길이 2, 4, 8, ..., N 의 묶음에 차례로": `size = 2` 에서 시작해 `size *= 2`, `while size <= N` 으로 일치. N = 2 이면 길이 2 하나, N = 1 이면 0 단계 (코드와 모순 없음).
- 묶음 하나에서 `N` 대신 `size`, `k` 대신 `j`: `W[j] = table[j * (N // size)]` 가 `exp(-2πij/size)` 임을 N = 16 전 단계에서 확인.
- `first = start + j`, `second = first + half`: 141~142행과 일치.
- 복소수 곱 (a, b) * (c, d) = (ac - bd, ad + bc): 143~147행에서 w = (a, b), second_value = (c, d), first_value = (e, f). `product_re = w.real*second.real - w.imag*second.imag` = ac - bd, `product_im = w.real*second.imag + w.imag*second.real` = ad + bc. 146~149행 줄 끝 주석 ("곱의 실수부 = ac - bd", "곱의 허수부 = ad + bc", "첫째 칸 = (e + 곱의 실수부, f + 곱의 허수부)", "둘째 칸 = (e - ..., f - ...)") 모두 일치.
- j: 기호 123행이 "허수 단위가 아니다" 라고 밝혔고, 이 블록 어디에서도 j 를 허수 단위로 쓰지 않는다.
- 기호 14개 모두 공식 또는 줄 끝 주석에서 쓰인다. 공식의 `table` 은 실제 코드 이름이라 기호 없이 허용.
- 지적: 아래 지적_1 ~ 지적_10 중 fft 항목.

### 3.4 ifft (154~176행)

- 공식 `x[n] = conj(FFT(conj(X)))[n] / N`: 수치로 `conj(FFT(conj(X)))/N` 와 오차 0, 직접 IDFT 와 1e-14. 코드 171행 `(a, -b)`, 175행 `(c / N, -d / N)` 와 부호, 순서 일치.
- 줄 끝 주석 `(a, b) -> (a, -b)`, `(c, d) -> (c / N, -d / N)` 는 맞다. 기호 7개 모두 쓰인다.
- 지적: 아래 지적_10.

## 4. 지적 (반증 시도 결과, 어긋남 0건 / 규칙 위반 또는 모호 11건)

### 지적_1 (misleading) fft 기호 117~118행 E/O 정의가 마지막 단계에서만 문자 그대로 참

- 원문: `E[k]   : 짝수 번째 샘플만으로 구한 절반 길이의 DFT`, `O[k]   : 홀수 번째 샘플만으로 구한 절반 길이의 DFT`
- 근거: size = N 일 때만 E = DFT(x[0::2]). 앞 단계의 E[j] 는 그 묶음 자신의 샘플 (x[r + m*(N/size)], r = order[start]) 의 짝수 위치 원소의 DFT 다. N = 16, size = 4, start = 0 이면 묶음이 담은 입력 번호는 [0, 8, 4, 12] 이고 E 는 x[0], x[8] 의 길이 2 DFT 다. 입력 전체의 짝수 번호 샘플이 아니다. 108행 "N 대신 size" 가 N 의 뜻은 바꾸지만 E/O 가 묶음의 샘플을 본다는 말은 없다.
- 제안: `E[k]   : 짝수 번째 샘플만으로 구한 절반 길이의 DFT (묶음 하나에서는 그 묶음의 샘플만 본다)` 와 `O[k]   : 홀수 번째 샘플만으로 구한 절반 길이의 DFT (묶음 하나에서는 그 묶음의 샘플만 본다)`

### 지적_2 (misleading) fft 공식 108~110행 갱신 전/후가 불분명하고 X 가 두 뜻으로 쓰임

- 원문: `E[j] = X[first], O[j] = X[second], W[j] = table[j * (N / size)]`
- 근거: 앞 두 식의 좌변은 `X[j]`, `X[j + size/2]` 이고 매핑 식은 E, O 를 `X[first]`, `X[second]` 로 정의해, 읽는 쪽에서 갱신 후 값으로 읽으면 순환 정의가 된다. 코드는 144~145행에서 `second_value = X[second]`, `first_value = X[first]` 로 갱신 전 값을 따로 받은 뒤 148~149행에서 쓴다. 또 기호 116행의 X[k] 는 "k번 주파수의 정보" 인데 매핑 식의 X[first] 는 중간 단계의 작업 리스트 값이다.
- 제안 (108~110행 교체):
  ```
  #     묶음 하나 (길이 size) 에서는 N 대신 size, k 대신 j 로 쓴다
  #     갱신 전 값: E[j] = X[first], O[j] = X[second], W[j] = table[j * (N // size)]
  #     갱신 후 값: X[first] = E[j] + W[j] * O[j], X[second] = E[j] - W[j] * O[j]
  #     first = start + j, second = first + half
  ```

### 지적_3 (misleading) fft 공식 109행 `N / size` 와 코드 `N // size`

- 원문: `W[j] = table[j * (N / size)]`
- 근거: 코드 143행은 `table[j * (N // size)]`. 파이썬에서 `/` 는 float 이라 그대로 쓰면 `TypeError list indices must be integers or slices, not float` (실행 확인). 수학적으로 값은 같으나 "코드와 정확히 일치" 규칙에 어긋난다.
- 제안: `table[j * (N // size)]` (지적_2 의 제안문에 이미 반영).

### 지적_4 (misleading) fft 128행 다른 파일의 함수 참조

- 원문: `# radix-2 FFT. dft 와 같은 결과를 빠르게 낸다`
- 근거: `dft` 는 `dft.py` 의 함수다. 규칙 "다른 파일 참조 금지" 에 걸린다. 같은 결과는 수치로 참이지만 (최대 오차 7e-12) 이 함수의 동작 설명이 아니라 다른 모듈과의 비교다. "빠르게" 도 코드가 하는 일의 서술이 아니다.
- 제안: `# radix-2 FFT. 비트 반전 순서로 늘어놓은 뒤 길이 2, 4, ..., N 의 묶음을 차례로 합쳐 X[0] ~ X[N-1] 을 구한다`

### 지적_5 (nit) fft 기호 117~118행 "짝수 번째 / 홀수 번째"

- 원문: `짝수 번째 샘플`, `홀수 번째 샘플`
- 근거: 한국어 "번째" 는 1부터 세면 2번째, 4번째 (= x[1], x[3], ...) 로 읽힌다. 코드의 E 는 x[0], x[2], ... 이다 (1-based 로 뒤바꾸면 오차 3.87). 프로젝트의 다른 기호 설명 `n번째 입력 샘플값 (x[n])` 이 0부터 세므로 일관은 되지만 처음 읽는 사람에게 모호하다.
- 제안: `E[k]   : 짝수 번호 (n = 0, 2, 4, ...) 샘플만으로 구한 절반 길이의 DFT`, `O[k]   : 홀수 번호 (n = 1, 3, 5, ...) 샘플만으로 구한 절반 길이의 DFT` (지적_1 의 괄호 문구와 합칠 것)

### 지적_6 (nit) fft 137행 "N 이 될 때까지"

- 원문: `while size <= N:  # 묶음 길이가 N 이 될 때까지`
- 근거: `<=` 라서 size = N 인 단계도 실행한다 (N = 16 에서 2, 4, 8, 16 네 단계 모두 실행 확인). "N 이 될 때까지" 는 N 에 닿으면 멈춘다고 읽혀 마지막 단계가 빠진 듯 보인다.
- 제안: `# 묶음 길이가 N 이하인 동안 (마지막은 size = N)`

### 지적_7 (nit) fft 132행 X 의 설명이 초기 내용만

- 원문: `X = []  # 입력을 비트 반전 순서로 늘어놓은 새 리스트. 입력 x 는 고치지 않는다`
- 근거: X 는 148~149행에서 제자리 갱신되어 151행에서 결과로 반환된다. 주석은 시작 시점의 내용만 말한다. 입력 x 불변은 참 (확인).
- 제안: `# 비트 반전 순서로 늘어놓은 새 리스트. 아래 반복에서 값이 갱신되어 결과가 된다. 입력 x 는 고치지 않는다`

### 지적_8 (nit) fft 기호 126행 쌍 표기 정의가 (a, b) 하나뿐

- 원문: `(a, b) : 실수부 a, 허수부 b 인 복소수`
- 근거: 공식 111행은 (c, d) 도 쓰고, 줄 끝 주석 143~149행은 (e, f) 까지 쓴다. 기호에는 (a, b) 만 있다.
- 제안: `(a, b), (c, d), (e, f) : 각각 실수부, 허수부 순서로 쓴 복소수`

### 지적_9 (nit) fft 107행 공식 안의 빈 `#` 줄

- 원문: 106행과 108행 사이의 `#` 빈 줄
- 근거: 머리말 형식은 "공식 줄, 빈 `#` 줄 하나, 기호 줄" 인데 fft 는 공식 구획 안에 빈 줄이 하나 더 있어 빈 줄이 두 개다. 의도적인 묶음 구분일 수 있어 취향에 가깝다.
- 제안: 107행을 지우거나, 구분이 필요하면 `묶음 하나 (길이 size) 에서는 ...` 앞에 빈 줄 대신 들여쓰기만 둔다.

### 지적_10 (nit) ifft 172행 `(c, d)` 가 리스트 전체에 붙음

- 원문: `Y = fft(conjugated)  # fft 결과 (c, d)`
- 근거: Y 는 복소수 N 개의 리스트이고 (c, d) 는 175행의 Y[n] 한 개의 실수부, 허수부다. 기호에는 (a, b) 만 정의돼 (c, d) 가 없다.
- 제안: `Y = fft(conjugated)  # fft 결과. Y[n] 의 실수부 c, 허수부 d` 와 기호 165행을 `(a, b), (c, d) : 각각 실수부, 허수부 순서로 쓴 복소수` 로.

### 지적_11 (nit) twiddle_table θ 와 쌍 표기

- 원문: 공식 `θ = 2πk / N`, 줄 끝 주석 97행 `번호 k 의 각도 θ (라디안)`, 98행 `W[k] = (cos(θ), -sin(θ))`
- 근거: θ 는 공식에서 식으로 정의될 뿐 기호 구획에 없고 코드 이름도 아니다 (코드는 `angle`). 98행의 `(x, y)` 쌍 표기는 이 블록에서 정의되지 않았다 ((a, b) 정의는 fft, ifft 블록에만 있다). 식 줄을 정의로 인정하는 규칙이면 θ 는 취하하고, 같은 패턴이 dft.py 에도 있다.
- 제안: 기호에 `θ    : 각도 (라디안). 코드의 angle` 추가, 98행 주석은 `W[k] = cos(θ) - j*sin(θ) 의 실수부 cos(θ), 허수부 -sin(θ) 를 complex 에 담아 table 에 붙인다` 처럼 쌍 표기를 빼기.

## 5. 검증 완료 (이상 없음)

- bit_reverse_order: 머리말 전체와 줄 끝 주석 전부, 예시 (N = 8, i = 3 -> 6), B = log2(N).
- twiddle_table: 공식 부호와 각도, 범위 k = 0 ~ N/2 - 1, 95, 96, 97, 98행 주석 (쌍 표기 제외).
- fft: 나비 공식 두 줄과 범위, "길이 2, 4, ..., N 의 묶음에 차례로", `first`, `second` 식, `W[j]` 매핑 (`//` 로 읽을 때), 복소수 곱 규칙과 `product_re`, `product_im` 및 (a, b), (c, d), (e, f) 주석, 148~149행 주석, j 가 허수 단위가 아니라는 기호와 j 의 비사용, 138~143행 줄 끝 주석.
- ifft: 공식과 코드, 171행, 175행 주석, 기호 대부분.
- 수치: fft = 직접 DFT (N = 8, 512, 실수/복소수), N = 16 전 단계 표 인덱스, ifft(fft(x)) = x.
