## 7. 발견 사항

### F1 (wrong) 프레임 크기와 버퍼 길이가 시험으로 고정되지 않는다

- 파일/함수: `tests\test_main.py` 의 `test_restore_overlap`(100-103), `test_restore_overlap_wav`(106-113)
- 줄: `assert tv.compare("겹침 있는 복원, 길이 812", main.restore_overlap(x), x)  # 입력으로 돌아온다`
- 근거: `y[n] / W[n % R] = x[n]` 은 W[r] 이 0이 아니면 어떤 R, N 에서도 성립한다. 그래서 `R = 16` 을 `R = 32`(R7), `R = 8`(R7c) 로, `N = 512` 를 `N = 256`(R7b) 로 바꿔도 `test_main.py` 15개가 모두 통과했다(`new=[] old=[]`, 각 4.4초, 4.0초, 14.2초). 이 프로젝트의 전제는 "프레임 16, FFT 512"인데 그 두 값이 어느 시험에도 걸려 있지 않다. 프레임 수 공식도 마찬가지다(R3d 는 값이 같지만 M 의 공식 자체는 검사되지 않는다). 가이드 단계_6 의 버퍼 표(프레임 0, 1, 31, 32 의 0, 495, 496, 511번)와 프레임 수 표도 어느 시험에서도 확인하지 않는다
- 제안: 분석에 들어가는 버퍼를 가로채어 확인하는 시험을 추가한다(원본에서 통과, R3, R3b, R3c, R3d, R6, R6b, R7, R7b, R7c, R10, R10b, R10c, R12, R13, R17 에서 실패를 확인).

```python
def test_restore_overlap_frames(monkeypatch):
    buffers = []
    real_analyze = main.analyze

    def spy(buffer, window):
        buffers.append(list(buffer))  # 분석에 들어가는 버퍼를 복사해 둔다
        return real_analyze(buffer, window)

    monkeypatch.setattr(main, "analyze", spy)
    main.restore_overlap(list(range(600)))  # x[n] = n. 600 은 16 의 배수가 아니다
    assert len(buffers) == 69  # ceil(600 / 16) + 31
    assert all(len(buffer) == 512 for buffer in buffers)
    assert [buffers[0][i] for i in (0, 495, 496, 511)] == [0, 0, 0, 15]
    assert [buffers[1][i] for i in (0, 495, 496, 511)] == [0, 15, 16, 31]
    assert [buffers[31][i] for i in (0, 495, 496, 511)] == [0, 495, 496, 511]
    assert [buffers[32][i] for i in (0, 495, 496, 511)] == [16, 511, 512, 527]
```
