| `print_dft_steps` | "칸 간격"의 칸이 주파수 칸과 겹친다 | "n 을 {step} 씩 건너뛰며 더한 합" |
| `print_dft_steps` | 줄 주석 4곳이 코드와 덜 맞는다 (함수 설명, `degree`, `step`, `while`) | 문구 고침 |
| `rounded` | 주석의 "-0" | "-0.0 을 0.0 으로" |
| `fft` 공식 | E, O 설명이 마지막 단계에서만 참이다 | "묶음에 든 샘플 중 짝수/홀수 자리" |
| `fft` 공식 | 바꾸기 전 값과 바꾼 뒤 값이 구분되지 않고, `N / size`가 코드의 `N // size`와 다르다 | "바꾸기 전", "바꾼 뒤" 두 줄로 나누고 `//`로 |
| `fft` 공식 | 공식 구획 안의 빈 줄, (c, d), (e, f) 미정의 | 빈 줄 삭제, 기호에 세 쌍 모두 적음 |
| `fft` 줄 주석 | "dft 와 같은 결과를 빠르게"(다른 파일 이야기), `while`, `X = []` | 문구 고침 |
| `ifft` | `Y` 주석의 (c, d)가 리스트 전체처럼 읽힌다 | "Y[n] = (c, d)", 기호에 (c, d) 추가 |
| `twiddle_table` | 줄 주석의 쌍 표기가 이 블록에서 정의되지 않았다 | "실수부 cos(θ), 허수부 -sin(θ)" |
| `idft` 공식 | c, d 가 코드 이름과 이어지지 않는다 | "(코드의 arrow_re, arrow_im)" |
| `dft.py` 1행, `main.py` import 주석 | 출력 함수가 빠져 있다 | "DFT 계산 과정 출력" 추가 |
| `dft`, `idft`, `print_dft_steps` | θ 가 코드의 `angle`과 이어지지 않는다 | 줄 주석을 "각도 θ (라디안)"으로 |

## 반영하지 않은 지적

| 지적 | 사유 |
|---|---|
| `dft`, `idft`, `twiddle_table` 기호에 θ 항목 추가 | 사용자가 보낸 예시가 θ 를 공식 줄에서 정의하고 기호에는 넣지 않는다. 예시 형식을 따른다 |
| `dft` 기호 `x[n]`에 "(실수)" 추가 | 사용자가 보낸 예시 문구를 그대로 쓴다 |
| `idft` 줄의 공백 정리 | 사용자가 쓴 줄이고 yapf 가 정리한다 |
| `rounded` 주석에 "가운데 값이면 짝수 쪽" 추가 | 표시용 반올림이라 주석을 짧게 둔다 |
| `step` 주석에 "N 이 1 이면 0" 추가 | 주석을 짧게 둔다. `while` 주석을 "1 이상인 동안"으로 고쳐 뜻이 통한다 |

## 검토 뒤 바뀐 것

검토 뒤 사용자가 "출력문을 쓰라고 한 적 없다, `dft`와 `idft`를 같은 형식으로 맞추라는 뜻"이라고 바로잡았다. `print_dft_steps`와 `rounded`는 안에서 뺐으므로 03번 노드의 지적은 적용 대상이 없어졌다. `dft`는 `idft` 형식으로 다시 썼고, 그 확인은 오케스트레이터가 직접 했다(옛 `dft`와 결과 차이 0.0, pytest `11 passed`).
