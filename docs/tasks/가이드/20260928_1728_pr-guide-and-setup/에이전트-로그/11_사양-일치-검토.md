| 사양 | 코드 | 결과 |

## 8. 주석 규칙 대조 (공식 블록)

| 함수 | 결과 |
|---|---|
| `hanning_window` | 공식 -> 빈 `#` -> 기호 순서, `def` 바로 위. θ 는 공식 안에서 정의(기존 `twiddle_table` 과 같은 방식). 기호 3개 모두 사용. 이상 없음 |
| `window_sums` | 순서 맞음. 다만 공식에는 `w[r + q*R]` 인데 기호에는 `w[i]`, 코드는 `i` 로 돌고 `q` 에 코드 이름이 없다 (지적 4) |
| `apply_window` | 이상 없음. `v[i]` 에 `(코드의 windowed[i])` 연결 있음 |
| `analyze` | `v[i]` 에 `(코드의 windowed ...)` 연결이 없다 (지적 1). 줄 주석이 정의 없는 N 을 쓴다 (지적 5) |
| `restore_overlap` | `x[n]` 이 입력과 결과 두 가지 뜻이고 둘 다 코드 이름 연결 없음 (지적 2). 공식 한 줄에 한국어가 섞임 (지적 3) |

줄 주석은 새 코드 전부 이름, 부호, 범위가 코드와 맞았다. 문서, 절, 단계 번호, 이력, 다른 파일을 가리키는 말은 새 코드에 없다. 새 코드의 비ASCII 문자는 Σ, θ, π 뿐이고 모두 공식 블록 또는 θ 줄 주석이라 허용 범위(CLAUDE.md "코드 주석" 행). 한글 외 구두점(긴 줄표 등)은 없다.

| `sums[R-1-n%R]` (합 표를 뒤집어 사용) | 동등 변이. `W[r] = W[15-r]` 이라 결과가 같다. 시험의 약점이 아님 |
| `restore_overlap` 안의 윈도우를 `[1.0]*N`, Hamming, sqrt-Hann, 주기형 Hanning 으로 교체 (합도 같은 윈도우로) | **6개 시험 모두 통과** |
| `R = 8`, `R = 32` | **6개 시험 모두 통과** |
| `N = 256` | **6개 시험 모두 통과** |

원인: 어떤 윈도우, 어떤 R, N 이든 분석과 합성에 같은 것을 쓰고 합으로 나누면 입력이 돌아온다. 복원 결과만 보는 시험은 그 값들을 고정하지 못한다. 04 단계_6, 단계_8의 확인 표 중 "버퍼 내용", "프레임 수 32 / 1031 / 1032", "나누기 전 ÷ 입력 15.968729 / 15.968833" 은 이 6개 시험이 확인하지 않는다(위 5절에서는 spy 와 `window_sums` 교체로 확인했다).

시험 값: `test_restore_overlap` 은 `tv.compare` 기본 허용 오차(절대 1e-5 + 상대 1e-9)를 쓴다. 입력 최대 12000 에서 허용치는 2.2e-5. 실제 오차는 7.3e-12. 04 단계_8 의 기준은 1e-9 이하.

## 10. FFT 쪽 변경사항이 있나

결론: **정확성을 위해 바꿀 것은 없다.**

- diff 에서 `fft`, `ifft`, `bit_reverse_order`, `twiddle_table` 은 한 글자도 안 바뀌었다.
- 새 코드가 `fft` 에 넘기는 것은 실수 float 리스트(길이 512), `ifft` 에 넘기는 것은 `fft` 가 돌려준 복소수 리스트다. 두 함수는 입력을 고치지 않는다(`X` 는 새 리스트).
- `fft` 결과는 `numpy.fft.fft` 와 상대 3e-16 으로 같다(5절 단계_7).

단, 04 단계_7 할 일 1("윈도우는 한 번만 만들어 두고 모든 프레임에 쓴다. 회전 인자 표와 비트 반전 순서도 같다")은 아직 지켜지지 않았다. `fft` 와 `ifft` 가 호출마다 `bit_reverse_order(512)`, `twiddle_table(512)` 를 다시 만든다(프레임마다 `fft` 1회 + `ifft` 안의 `fft` 1회 = 2회). L = 4096 에서 `fft` 574 번 호출, 프로파일 기준 표 만들기가 `fft` 시간의 약 27 %.

측정(`restore_overlap` L = 4096, 표를 호출 밖에서 한 번만 만들어 재사용하도록 바꿔 끼움): 표 매번 1.70 초, 한 번만 1.35 초(21 % 단축), 출력은 완전히 같음(`a == b` True). 표 한 번 만들기를 하려면 `fft`, `ifft` 가 표를 인자로 받거나 밖에서 만든 표를 쓰는 변경이 필요하다. 동작 보존이므로 사용자가 정할 일이다.

### 지적 2 (misleading) `restore_overlap` 기호에서 `x[n]` 이 두 가지 뜻이고 코드 이름 연결이 없다

- 대체안: 공식 `z[n] = y[n] / W[n % R]` (또는 03 처럼 `x̂[n]`), 기호
  - `x[n] : n번째 입력 샘플값 (코드의 samples[n])`
  - `z[n] : 되돌린 n번째 샘플값 (코드의 restored[n])`

### 지적 3 (nit) `restore_overlap` 공식 줄에 한국어가 섞이고 `b`, `w` 가 첨자 없이 쓰인다

- 파일: `src\main.py`, 줄 274, 275
- 텍스트: `y[n] = y[n] + IFFT(X)[i] 의 실수부,  n = (m + 1)*R - N + i`, `X = FFT(b * w)` (기호는 `b[i]`, `w`)
- 근거: 공식 줄 안에 "의 실수부" 라는 말이 들어가 있고 `실수부` 는 기호에 없다. `FFT(b * w)` 의 `b` 는 기호에 `b[i]` 로만 있다. 프로젝트 규칙은 `.real` 로 읽는 것을 복소수 꺼내기로 정한다.
- 대체안: `y[n] = y[n] + Re(IFFT(X)[i]),  n = (m + 1)*R - N + i` 와 기호에 `Re : 복소수의 실수부 (코드의 .real)` 추가, `X = FFT(v)` 와 `v[i] = b[i] * w[i]` 로 풀어 쓰거나 `b : 프레임 m 의 버퍼 (코드의 buffer)` 로 첨자 없는 이름을 기호에 둔다.

### 지적 4 (nit) `window_sums` 공식과 기호의 첨자가 어긋난다

- 파일: `src\main.py`, 줄 211, 220
- 텍스트: 공식 `W[r] = Σ w[r + q*R]`, 기호 `w[i] : 윈도우의 i번째 값 (코드의 window[i])`, `q : 더할 차례`
- 근거: 공식에는 `i` 가 없는데 기호에 `w[i]` 가 있고, 코드 228줄은 `for i in range(r, N, R)` 로 `i` 가 돈다. `q` 는 코드에 이름이 없다(보폭 R 로 숨음). `i = r + q*R` 라는 연결이 어디에도 적혀 있지 않다.
- 대체안: 공식을 `W[r] = Σ w[i],  i = r + q*R` 로 쓰고 기호에 `i : 윈도우 안에서의 번호. r + q*R (코드의 i)`, `q : 더할 차례 (코드에서는 i 를 R 칸씩 늘리는 것)`.

### 지적 5 (nit) `analyze` 줄 주석이 정의 없는 N 을 쓰고 공식에 범위가 없다
