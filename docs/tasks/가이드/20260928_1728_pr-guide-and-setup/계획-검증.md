## 3. 근거 검증 (단계별 게이트)

### 3.1 실패 시나리오

| 시나리오 | 일어나는 조건 | 결과 | 대응 |
|---|---|---|---|
| 실패_1 문법 예시가 해답이 된다 | 예시 소재를 과제에서 가져오거나, 예시 여러 개를 이으면 단계 하나가 완성되는 경우 | 손코딩 목적이 무너진다. 사용자 조건 2 위반 | 계획 Step 4의 기준표(소재, 길이, 내용)와 코드 블록 전수 점검 |
| 실패_2 가이드의 기대값이 사용자 구현과 어긋난다 | 사용자가 1/N을 순방향에 두는 등 다른 규약을 택한 경우 | 사용자가 맞는 구현을 틀렸다고 판단한다 | 기대값마다 전제한 규약과 입력 조건을 적는다 (위험_7) |
| 실패_3 출처를 확인하지 못한 공식을 인용으로 쓴다 | 기억에 의존해 절 제목을 적는 경우 | 자료 근거 규칙 위반 | 원문을 연 것만 인용하고 나머지는 유도로 표기 (위험_4) |
| 실패_4 1.5 모사와 자체 설계가 섞여 읽힌다 | 복원 쪽을 1.5 사양처럼 서술하는 경우 | 사용자가 1.5에 없는 동작을 1.5 동작으로 오해한다 | 02 문서에 구분을 명시 (분석 제약_1) |
